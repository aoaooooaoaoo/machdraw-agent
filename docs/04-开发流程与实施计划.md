## 0. 结论先行（12 条架构决策）

| # | 决策 | 理由 |
|---|---|---|
| D1 | **照搬参考作品的四层架构与"契约驱动可插拔模块 + 七类事件流"** | 9 个模块并行开发的唯一可行组织方式；已被验证 |
| D2 | **后端 Python（FastAPI），前端 React + TypeScript** | 几何/检索/公差计算全在 Python 生态；React 的 3D 生态最成熟 |
| D3 | **三视图投影放服务端算，不放浏览器** | opencascade.js 体积 10–25MB、HLR 绑定不稳；正交三视图**只需算一次并缓存**，无实时性压力 |
| D4 | **MVP 期三视图离线预生成（SVG 图元 JSON），二期再上运行期 STEP 解析** | 先保证"能演示"，把最大技术风险后置但不消失 |
| D5 | **不引入向量数据库**（Milvus 是过度设计） | 语料 40–60 万字 → 约 1200–1800 个子块，`numpy` 矩阵点积全量扫描 < 10ms，一个 `.npy` 文件即可 |
| D6 | **凡能确定性计算的绝不让 LLM 生成**：公差、投影、剖面线、螺纹参数、圆弧切点 | 零幻觉的唯一来源，也是评审最认的技术点 |
| D7 | **图文双模态检索**：图独立建索引（图号/图名/所属节/可回渲原页） | 参考作品纯文本 RAG 自认"图片未文字化"，制图课这样会丢一半知识 |
| D8 | **符号规范化层**是检索的前置处理（`⌀20`→`phi20`、`Ra3.2`→`ra3.2`、`H7` 保原样） | 制图提问大量是符号/数值型，纯语义向量对符号几乎无效 |
| D9 | **探针评测集第一天就建**（40–60 题，含"近域干扰题"） | 策划案一期唯一验收项是"回答准确率"，没有探针就无法验收 |
| D10 | **单 Docker 交付 + 注册即用** | 可推广性的硬证据，答辩安全垫 |
| D11 | **判分能力分三级，先做 L1**：L1 离散答案（选择/判断/填空/计算）全自动 → L2 标注题（尺寸/粗糙度/公差/螺纹标记）半自动 → L3 作图题只给"通过/存疑/未通过"三档，**不承诺分数** | 03 文档实测：82% 是作图题、答案全是"图"没有步骤，可自动判分不足 10%；L1 恰好覆盖考试样题的"送分区"，性价比最高 |
| D12 | **版权分层架构**：内部层可挂原图/原题做评测，对外层只输出知识点、步骤、自写示意图 | 现有题库底料（高教社第 6 版习题集 + 教研室解答 + MOOC 水印作业册）**版权风险高，仅限内部教研**；分层后未来换源只替换内部层，Agent 逻辑不动 |

## 2. 技术选型（含备选与理由）

### 2.1 前端

| 项 | 选型 | 备选 | 理由 |
|---|---|---|---|
| 框架 | React 19 + TypeScript + Vite | Vue 3 | 3D/图谱生态 React 更强（r3f、react-force-graph） |
| 样式 | Tailwind CSS + shadcn/ui | Ant Design | 三栏工作台需要细粒度自定义；AntD 偏后台感 |
| 3D | three.js + `@react-three/fiber` + `@react-three/drei` | Babylon.js | 生态与文档量级；GLB 加载、clipping plane 现成 |
| 2D 三视图 | **SVG（React 直接渲染图元）** | Canvas / WebGL | 需要"彩色虚线辅助线 + 逐条高亮 + 可点击"→ DOM/SVG 最省事 |
| 图谱 3D 星图 | three.js 自写（节点球 + 连线 + OrbitControls） | react-force-graph-3d | 需要"点星球相机飞过去绕它转"，自写可控性更高 |
| 状态 | Zustand | Redux | 轻、适合"事件流驱动" |
| 流式 | `fetch` + ReadableStream（POST SSE） | EventSource | 需要 POST 带上下文，EventSource 只支持 GET |
| 公式/符号 | MathJax 或 KaTeX（按需） | — | 尺寸标注少公式，按需引入 |

### 2.2 后端

| 项 | 选型 | 说明 |
|---|---|---|
| 框架 | FastAPI + Pydantic v2 | 与前端共享 schema（自动生成 TS 类型） |
| 流式 | `StreamingResponse` + SSE 格式 | 七类事件逐帧下发 |
| DB | SQLite + SQLModel | 单容器友好；会话/错题/学情事件 |
| 检索 | `numpy` + `rank_bm25` + `jieba` | 无向量库 |
| 几何（二期） | **OCP**（`pip install cadquery-ocp`）或 `pythonocc-core`（conda） | 见 §2.3 |
| CV | `opencv-python` + `scikit-image` | 手绘线检测、线宽测量、角度测量 |
| LLM | DeepSeek（文本）+ Qwen-VL / GPT-4o（视觉），OpenAI 兼容 SDK | 单点适配层，便于换模 |

### 2.3 几何内核：三条路线与决策

| 路线 | 做法 | 优点 | 缺点 | 采纳 |
|---|---|---|---|---|
| **A（MVP 采用）** | 离线用 OCCT/FreeCAD 脚本把每个模型预先算好三视图 → 输出 `{线段, 圆弧, 线型, 视图}` JSON + SVG；同时导出 GLB | 零运行期依赖、零性能风险、演示稳定 | 模型固定，不能任意 STEP 上传 | ✅ 一期 |
| **B（二期）** | 服务端 `OCP`/`pythonocc`：`STEPControl_Reader` → `HLRBRep_Algo`（隐藏线消除）→ 图元 → SVG/GLB | 支持任意 STEP/IGES 上传 | 需装重依赖；HLR 对复杂件慢（秒级） | ✅ 二期 |
| **C（不采用）** | 浏览器 `opencascade.js` WASM | 无服务端算力 | 10–25MB wasm 首屏；绑定不全；低端机卡 | ❌ |

> **关于"旋转时三视图同步更新"的澄清（重要）**：
> 正交投影下，**相机绕模型转圈（orbit）不改变三视图**——三视图由"模型相对标准方向"决定。所以 PPT 这句话的正确实现是两层：
> 1. **orbit 旋转** → 三视图**不重算**，只做"视觉联动"：3D 高亮某特征 ↔ 三视图中对应图元高亮，并画出彩色辅助线演示"长对正/高平齐/宽相等"；
> 2. **改变主视方向（重新定向）** → 才重算三视图（且只需算 6 个正交方向，可预生成缓存）。
>
> 这样既符合教学内容，也把"实时 HLR"这个性能陷阱拆掉了。**必须在方案里写清楚，否则会被评审问倒。**

## 4. 核心契约（先写这个，再写业务）

### 4.1 六类事件 + 终止哨兵（SSE `data:` 行，JSON）

> ★ 2026-11-07 已对参考作品线上站点抓包验证，**下面的命名是按它的实测协议对齐的**（详见 05 文档），不要自己另起一套名字。

```jsonc
{"type":"thinking",   "seq":1, "text":"学生在问内螺纹剖视图，先检索国标与教材"}
{"type":"tool_call",  "seq":2, "id":"c1","name":"kb_search","label":"检索『内螺纹 剖视』","args":{"query":"内螺纹剖视图画法","top_k":6}}
{"type":"tool_result","seq":3, "id":"c1","summary":"命中 8 段原文证据","detail":"…\n引用时标注 chunk_id，只依据以上证据作答。"}
{"type":"artifact",   "seq":4, "artifactType":"evidence","data":{...}}
{"type":"token",      "seq":5, "text":"内螺纹剖视图中，"}
{"type":"error",      "seq":6, "code":"KB_GATE_REJECT","message":"知识库未收录该主题"}
{"type":"done"}
data: [DONE]
```

**关键细节（照做能省很多事）**：
1. 正文流式事件名是 **`token`**，不是 `text`（`text` 只用于 `thinking` 的增量字段）。
2. 帧间可夹**非 SSE 进度行** `{"revision":N}`（无 `data:` 前缀），用于前端同步状态版本。
3. `tool_result.detail` **末尾固定追加一句约束**：`引用时标注 chunk_id，只依据以上证据作答。` —— 这是"强制 RAG 防幻觉"的双保险之一（另一半在系统提示词）。
4. 流以 `data: [DONE]` 结束。
5. 参考作品是 1–2 字符一帧（一次问答 1418 帧），**我们改为 20–50 字符一帧**，减少事件量。

### 4.2 画布 Artifact（`artifactType` + `data`，前端按 type 认领）

> 用**语义名**，禁止用 `module1/module2` 这类编号——参考作品就是编号混乱（缺 module3/5/6）的反面教材。

| artifactType | 用于模块 | data 要点 |
|---|---|---|
| `evidence` | kbrag / chat | 证据卡数组：`chunkId, documentId, documentTitle, category, section, score, content, snippet` |
| `comparison` | projection | 成对图 + 差异点（`bbox, 类型, 说明`）+ 题目/选项 |
| `annotation` | wrongbook / feynman | 原图/原文 + 标注数组（`bbox` 或 `span`, 三色标签, 点评） |
| `three_view` | sandbox3d | `model_id` + GLB url + 四视图图元（主/俯/左/轴测）+ 辅助线 + 当前高亮特征 id |
| `graph` | graph | 节点/边 + 节点状态色 + 当前聚焦节点 + 推荐前置路径 |
| `tolerance` | tolerance | 基本尺寸/代号/极限偏差/极限尺寸/配合类型/公差带图 + 工艺卡 |
| `coach` | coach | 步骤脚本数组（`step, 说明, 图元增量`） |
| `quiz` | projection / wrongbook | 题干 + 图 + 选项/作答区 + 判分规则 |

**chunkID 编码规范（照它的做法，父块 ID 内嵌，省一次查表）**：
`chk_<documentId>_<4位父块序号>_<4位子块序号>`，例 `chk_doc_a163fb06_0008_0000` = 第 8 父块的第 0 子块。

### 4.3 模块 manifest（后端 `registry.py` 读取）

```python
class ModuleManifest(BaseModel):
    id: str                  # "tolerance"
    name: str                # "公差与配合侦探"
    canvas_kinds: list[CanvasKind]      # 本模块认领的画布类型
    tools: list[str]                    # 本模块可用的工具名
    system_prompt: str                  # 模块级提示词（含边界约束）
    entry_examples: list[str]           # 左栏展示的示例问法
    requires: list[str]                 # 依赖的资源 id（如 "gb1800_table"）
```

**新增一个模块 = 新建 `apps/api/app/modules/<id>/` + `apps/web/src/modules/<id>/` 两个目录，不改公共文件。**

## 5. 九个模块的实现方案

> 每格给出：输入 → 处理 → 输出画布 / 依赖 / 预估工作量（人日，1 人全职）。
> 工作量按"熟练开发者 + 代码助手"估，仅用于排期比例，不是承诺。

| # | 模块 | 输入 | 处理要点 | 画布/输出 | 依赖 | 工作量 |
|---|---|---|---|---|---|---|
| 0 | **全局对话** | 文本/语音/图片 | LLM 意图识别 → 路由到模块或直接 ReAct → 流式 | 文本 + 工具卡 + 随模块切换画布 | 工具总线、事件流 | 6 |

## 6. 知识库建设流水线（离线，与开发并行）

```
① 采集        ② 解析            ③ 结构还原        ④ 切分          ⑤ 索引         ⑥ 校验
kb/ 原始文件 → 文本+图块+页坐标 → 标题树/条款树/题号 → 四套切分器 → 向量+BM25+IDF → 覆盖矩阵/gap
```

### 四套切分器（必须分开，不能一刀切）

| 切分器 | 对象 | 规则 |
|---|---|---|
| `TextbookSplitter` | 教材 | 父块 = 章/节（按 Heading）；子块 = 合并短段到 200–350 字；图块单独出 |
| `StandardSplitter` | 国标 | 父块 = 标准号；子块 = **条款号**（如 `5.1`）；表格 **一行一块**，表头拼进前缀；带 `std_no + version + effective` |
| `SlideSplitter` | 课件 pptx | 父块 = 文件；子块 = 页 + 页内文本块；带 `slide` 页码；图注单独出 |
| `ExerciseSplitter` | 习题/真题 | 一题一块；字段 = 题干/图/题型/知识点/难度/来源；**答案与解析写入独立索引** |

### 图块索引（★ 机械制图特有，参考作品没有）

```json
{
  "figure_id": "FIG-05-12",
  "doc_id": "TB", "chapter": "第五章 组合体", "section": "5.3 尺寸标注",
  "page": 112, "bbox": [x0,y0,x1,y1],
  "caption": "图5-12 尺寸标注示例",
  "caption_source": "ocr|caption_style|vlm",
  "structure_tags": ["线性尺寸","基准","圆角"],
  "kp_ids": ["KP-DIM-003"],
  "renderable": true
}
```
命中图块时，右栏**直接回渲原页图并裁剪到 bbox**——这是"附教材与 GB/T 原文截图"（策划案原话）的落地方式。

### 覆盖矩阵（gap 分析，上线前必须做）

`大纲章节 × 教材节 × 课件 × 国标条款` 的覆盖表；空缺项要么补料，要么在答案里明确"本课程不覆盖"。**不要让门控替我们背锅**（参考作品踩过这个坑）。

### 题库资产的"已就绪度"（详见 03 文档）

| 已有 | 状态 | 可直接用吗 |
|---|---|---|
| **252 题索引 CSV**（`docs/题库索引_习题集第6版_252题.csv`） | 书签全量解析，含章节/书页/题号/解答页/模型页/OCR 题面 | ✅ 直接入库，OCR 题面待校字 |
| 455 页解答册（一题一图 + 191 张三维模型页） | 纯位图 | 需切图/红线提取后才能用 |

| 期中/期末样题题库面（1,711 字矢量文字） | 可直接逐字引用 | ✅ 但只有 11+10 页 |

## 9. 评估方案（照抄探针法并强化）

### 9.1 探针集 `eval/probes.jsonl`

```jsonl
{"id":"P001","domain":"in","q":"内螺纹剖视图中小径用粗实线还是细实线？","expect_docs":["GB/T 4459.1","教材 9.2"],"min_coverage":0.6}
{"id":"P026","domain":"out","q":"铝合金焊接工艺参数怎么定？","expect_refuse":true}
{"id":"P031","domain":"near","q":"齿轮的焊接符号怎么标注？","expect_refuse":true,"note":"近域干扰：制图里有齿轮、有符号，但没有焊接"}
```
- 课内 25–40 题（覆盖 8 大知识板块）
- 课外 10 题（明显超纲）
- **近域干扰 5–10 题**（词面沾边但课程不教）——这是分离带的关键

### 9.2 指标

| 指标 | 目标 | 测法 |
|---|---|---|
| 课内检索命中率 | ≥ 95% | 期望文档出现在 top-8 |
| 课外拒答率 | ≥ 95% | 输出含"知识库未收录" |
| 门控分离带 | > 0.15 | 课内最低覆盖率 − 课外最高覆盖率 |
| Hit@3 / MRR@5 | 记录并扫 λ | 与参考作品同口径对比 |
| 引用完整率 | 100% | 每条结论都有 ref |
| 公差计算准确率 | 100% | 20 组固定样例回归 |
| 三视图正确率 | 100% | 20 个模型对照教材标准答案 |
| 找茬检出/误报 | 待定基线 | 50 张标注样本 |

### 9.3 回归机制
`eval/run.py` 一键跑全部探针 → 输出 `eval/results/<日期>.json` + Markdown 对比表；**任何合并到主干前必须跑**，指标退化就阻断。

## 13. 一句话总结
