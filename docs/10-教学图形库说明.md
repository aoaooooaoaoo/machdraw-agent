## 2. 每张图讲什么、容易画错的地方

### 2.1 FIG-LINETYPE —— 图线线型对照表
**讲什么**：六种图线（粗实线、细实线、虚线、细点画线、波浪线、双点画线）并排成一张表，
左边是线型样本，中间标线宽（粗 = d、细 = d/2），右边写用途，底部四条国标规定。
一张图解决"哪种线画什么、画多粗"。

**容易画错**：
- 把点画线画成"长长短短的虚线" —— 国标点画线是 `长画 18 + 间隔 4 + 短画 3 + 间隔 4`，
  本图直接用 `stroke-dasharray="18 4 3 4"`，短画必须能看出是"画"不是"点"。
- 双点画线（相邻辅助零件轮廓）和点画线混用 —— 两段时间间隔都不一样，本图 `20 4 3 4 3 4`。
- 波浪线用手绘正弦曲线 —— 本图故意让幅度、相位都轻微漂移（`svgkit.wave_pts`），
  因为国标要的是"断裂线"，规则正弦反而是错的。

### 2.2 FIG-SANSHITU-BASE —— 三视图形成与三等规律
**讲什么**：L 形块（100×60×70 mm，k = 2 px/mm）按第一角投影展开成主、俯、左三个视图，
用**三种颜色的虚线**分别画出三条投影关系：蓝 = 长对正、红 = 高平齐、绿 = 宽相等，
绿的还配了一根 45° 辅助线，把俯视图的宽搬到左视图。

**几何是硬的**：主视图 x ∈ [120,320]、俯视图 x 同样 ∈ [120,320]（长对正）；
主视图 y ∈ [150,290]、左视图 y 同样 ∈ [150,290]（高平齐）；
俯视图高 120 px、左视图宽 120 px（宽相等，都是 60 mm×2）。三个视图都标了尺寸，可直接量。

**容易画错**：
- 45° 辅助线位置放反：它必须让"俯视图的 y"映射到"左视图的 x"，本图取 (400,340)→(520,460)，
  即 x = y + 60；放反了宽相等就搬到反方向去。
- 左视图里 35 mm 的台阶面其实**看不见**（被左边高的部分挡住），必须画虚线 —— 本图 `stroke-dasharray="6 4"`。
- 三个视图的名称标注不能盖住投影辅助线（本图把标签放在视图正上方、辅助线留空处）。

### 2.3 FIG-SANSHITU-EXAMPLE —— 组合体三视图示例
**讲什么**：底板 90×50×20 + 左端台阶 40×50×25 + Ø16 竖直通孔，按第一角排三个视图，
并用紫色引出线点出**三个方向的尺寸基准**：底面（高）、左端面（长）、对称中心面（宽）。
底部一句"读图顺序"给出方法。

**容易画错**：
- 通孔在三个视图里的线型：主视图（外形视图）里是被遮住的 → **虚线**；俯视图俯视可见 → **粗实线圆**；
  左视图里被台阶挡住 → 虚线。三处线型不同，是学生最常统一画错的地方。
- 左视图里"底板顶面"被台阶挡住，要画一条**横贯全宽的虚线**（z = 20 处）。
- 尺寸基准不是随手标三个箭头：同一方向的尺寸必须从同一个基准出发，所以长度都从 80 那一侧标。

### 2.4 FIG-LIUGESHITU —— 六个基本视图的配置
**讲什么**：主视图居中，仰视图在上、俯视图在下、右视图在左、左视图在右、后视图在左视图之右，
六个视图共用同一个形体（80×40×50，中间 Ø20 通孔），一眼看清"哪个视图摆在哪"。

**容易画错**：
- 方向记反（第一角：俯视图在主视图**下**方、左视图在**右**方；第三角正好相反）。
- 后视图摆错位置（应放在左视图右边，不是最左边）。
- 六个视图的"长对正/高平齐/宽相等"对应关系：本图下面三句话把分组写清楚了。

### 2.5 FIG-POUSHI-QUAN —— 全剖视图
**讲什么**：法兰 Ø80 + 筒体 Ø50 + 内孔 Ø28 的圆筒。左边外形视图（内孔画虚线），
右边 A—A 全剖视图（内孔轮廓变成粗实线、空腔不画剖面线、剖面线 45° 细实线）。
下方俯视图用**粗短画 + 箭头 + 字母 A**标出剖切位置线，箭头指向投射方向。

**容易画错**：
- 剖切符号三件套缺一：粗短画（3 px）、箭头（指投射方向）、相向的字母 A；剖视图上方还要注 A—A。
- 空腔里画了剖面线 —— 本图内孔区域干净留白。
- 剖面线没画到粗实线为止（要么画进空腔、要么离轮廓差一截）。
- 剖切平面通过轴线（对称面）时，剖视图里"内孔"就变成两条竖直粗实线，不是虚线。

### 2.6 FIG-POUSHI-BAN —— 半剖视图
**讲什么**：对称法兰套筒（法兰 Ø80、筒体 Ø60、内孔 Ø24）以**对称中心线为界**，
左半画剖视（孔壁粗实线 + 剖面线）、右半画视图（只有外形轮廓）。
一个视图同时给出内形和外形，这是半剖存在的唯一理由。

**容易画错**：
- 分界线画成粗实线 —— 必须是**细点画线**（对称中心线）。
- 视图半侧还画虚线 —— 半剖的视图半侧**不画虚线**（内部形状已由另半侧表达），本图右侧故意留空。
- 剖面线一直画到中心线 —— 应画到孔壁粗实线为止；本图左半的剖面线只到 x = 456（Ø24 孔壁）。
- 对称中心线上有轮廓（如键槽）时不能用半剖，应改局部剖（图注 ⑤ 已写）。

### 2.7 FIG-POUSHI-JUBU —— 局部剖视图
**讲什么**：120×50 平板中间有 Ø20 竖直通孔。用一条**手画波浪线**围出剖切区域，
区域内孔壁画粗实线、区域外仍按外形画虚线 —— 既看到内形，又保住大部分外形。

**容易画错**：
- 波浪线画成规则正弦 — 本图幅度/相位都做了漂移。
- 波浪线与轮廓线重合、或画在孔槽空腔上（那里没有实体可以"断裂"）。
- 只画了剖切侧的实线，忘了区域外那条虚线（孔的下半段仍是隐藏的）—— 本图专门把上下两段
  线型做成不同（上粗实线、下虚线），这个对比就是考点。
- 波浪线画得太长、跨越多个结构，导致图形支离破碎。

### 2.8 FIG-DUANMIAN —— 断面图 vs 剖视图
**讲什么**：同一零件（Ø40 立柱 + 肋板，立在 100×100 底板上）、同一剖切位置、同一投射方向，
左边只画**断面形状**（圆 + 肋板），右边除了断面还要画出剖切面**后方可见的底板轮廓**。
两张图并排放，差别一眼可见。

**容易画错**：
- 断面图里多画了后面的轮廓（那就变成剖视图了）。
- 剖视图里给"后面的轮廓"也画了剖面线（底板没被剖到，不能画剖面线）。
- 断面轮廓的圆弧与肋板交接处没处理：本图用一条复合路径（大圆弧 + 肋板折线）合成封闭轮廓，
  圆弧与肋板相交的那段弧被"吃掉"，不是简单叠加一个圆和一个矩形。

### 2.9 FIG-POUMAINXIAN —— 相邻零件剖面线方向
**讲什么**：零件 1（凹形块）与零件 2（凸块）装配在一起后同时被剖切，
剖面线一个 45°、一个 135°，方向相反，两个零件一眼可分。下面五条把国标规定写全。

**容易画错**：
- 两个相邻零件画成同一方向同一间距 —— 分不清是谁。
- 同一零件在不同剖视图里剖面线方向变了 —— 读图时就认不出这是同一个零件。
- 接触面画成两条线 —— 相邻零件接触面只画**一条**粗实线。
- 把"方向相反"当成唯一解：方向相同但**间距不同**也合规（图注 ③）。

### 2.10 FIG-GONGCHA-DAI —— 公差带图（Φ30 H7/k6）
**讲什么**：零线 + 孔 H7（0 ～ +21 μm）+ 轴 k6（+2 ～ +15 μm），标出 ES/EI/es/ei，
右侧用括号量出 Xmax = ES − ei = +21 − 2 = **+19 μm**、Ymax = es − EI = 15 − 0 = **15 μm**，
并点明这是过渡配合。

**数值来源**：不是抄书，是调项目自带的 GB/T 1800 引擎 `apps/api/app/domain/tolerance.py` 算出来的
（`_tools/check_tolerance_values.py` 可复跑）：

```
Φ30 H7 = 0 / +21 μm    Φ30 k6 = +2 / +15 μm
```

**⚠️ 与任务书的一处出入（已按国标纠正）**：任务书里写"轴 k6 公差带（跨零线）"。
实际 k6 的下偏差 ei = **+2 μm > 0**，整条公差带都在零线上方，**并不跨零线**；
真正跨零线的是 js / j / J 这类对称偏差。图按 GB/T 1800 的真值画，并在图注 ⑤ 里明确写了这一点
—— 教学图不能把一个错误概念画进学生的肌肉记忆里。

**容易画错**：
- 孔、轴公差带画在两条不同的零线上（必须同一条零线才能比高低）。
- 上下偏差写反（孔用 ES/EI、轴用 es/ei，大写对孔、小写对轴）。
- 把 μm 和 mm 混着标（本图整轴单位统一 μm，数值另用 mm 写：+0.021 等）。

### 2.11 FIG-YUANHU-LIANJIE —— 圆弧连接步骤（R10 连接两垂直直线）
**讲什么**：三步。① 以 R 为距离作两条平行线 → 交点 O 即圆心；② 过 O 向两条已知直线作垂线
→ 垂足 T1、T2 即切点；③ 以 O 为圆心、R 为半径在 T1、T2 之间画弧，并把多余线段擦掉。
第 ③ 幅特意画成**完成状态**（直线只画到切点），不是还留着尖角。

**容易画错**：
- 不先求圆心就"目测接弧"，弧与直线接不上（不相切）。
- 求出圆心却直接从圆心画到直线：那样弧与直线是**相交**不是**相切**，必须先求切点。
- 第 ③ 步忘了擦掉原来的直角尖角（本图第 ③ 幅水平线止于切点、竖直线始于切点）。
- 切点方向搞反（内切/外切时圆心在直线哪一侧）。

### 2.12 FIG-LUOWEN —— 螺纹比例画法（外螺纹 / 内螺纹剖视）
**讲什么**：左边外螺纹（牙顶 d 粗实线、牙底 d₁ = 0.85d 细实线、螺纹终止线粗实线、
端视图里牙底圆画约 3/4 圈细实线），右边内螺纹剖视（牙顶 D₁ 粗实线、牙底 D 细实线、
剖面线画到牙顶粗实线为止）。两张并排，"粗线是牙顶"这条规律一眼对上。

**容易画错**：
- 内外螺纹的粗细分反 —— **外螺纹大径粗、内螺纹小径粗**（都是"牙顶粗"），这是最高频错误。
- 端视图里画成两个整圆 —— 牙底圆必须画约 **3/4 圈**（留 1/4 不画）。
- 螺纹终止线画成细实线、或没画到牙顶。
- 把螺纹按真实牙型画成锯齿 —— 国标要求按**比例**画（d₁ ≈ 0.85d），不画牙型。
- 内螺纹剖视里剖面线画进空腔。

### 2.13 FIG-BIAOMIAN —— 表面结构代号（Ra）
**讲什么**：左边三个符号并列——基本符号（两条 60° 细实线）、去除材料符号（加短横线）、
不去除材料符号（加小圆），并示范 "Ra 3.2" 写在横线上方；右边一张表把
Ra 0.4 / 0.8 / 1.6 / 3.2 / 6.3 / 12.5 与常用加工方法、表面特征对照起来。

**容易画错**：
- 三个符号混用（把不去除材料的小圆画到加工面上）。
- 数值写在横线**下方**或写在符号里（应写在上方，单位 μm 省略不写）。
- 把 Ra 当成"越大越光滑"（正好相反：数值越小越光滑）。
- 同一表面重复标注（只注一次）。

### 2.14 FIG-CHICUN-SIYAOSU —— 尺寸注法四要素
**讲什么**：左边一个正确标注的矩形，用 ①②③④ 圆标点出尺寸界线、尺寸线、箭头、尺寸数字；
右边两个反例（数字被尺寸线穿过、尺寸线画成粗实线）打 ✗，下面四条把规范写全。

**容易画错**：
- 尺寸线用粗实线（必须细实线），或用轮廓线/轴线直接代替尺寸线。
- 尺寸数字被尺寸线穿过（数字处要断开，或写在线上方）。
- 尺寸界线没有超出尺寸线 2～5 mm。
- 箭头没顶到尺寸界线、或一端有箭头一端没有。

### 2.15 FIG-GONGCHA-PEIJIAN —— 三种配合的公差带对照
**讲什么**：同一基本尺寸 Φ30 下并排三个公差带图：H7/g6（孔带在轴带之上 → 间隙）、
H7/k6（两带重叠 → 过渡）、H7/s6（孔带在轴带之下 → 过盈）。三张图用同一竖直比例尺，
"看相对位置判配合"这条方法直接可视化。

**数值来源**：同样来自项目 GB/T 1800 引擎：
`g6 = −20/−7`、`k6 = +2/+15`、`s6 = +35/+48`，配合量
`H7/g6：Xmax=+41 Xmin=+7`、`H7/k6：Xmax=+19 Ymax=15`、`H7/s6：Ymax=48 Ymin=14`。

**容易画错**：
- 三张分图各用各的比例尺，导致"看起来差不多高"，比不出来（本图统一 4.6 px/μm）。
- 把"重叠"画成"相切"就算过渡（重叠必须真的相交）。
- 过盈配合仍去算"最小间隙"（应算最小过盈，是负的间隙）。

## 3. 制作规范（这批图统一遵守）

| 项 | 做法 |
|---|---|
| 根元素 | `xmlns` + `viewBox` + `width="100%" height="100%"` + `style="height:auto;display:block"`（CSS 覆盖属性里的 100%，实际按 viewBox 比例自适应） |
| 配色 | 线条/文字默认 `stroke="currentColor"` / `fill="currentColor"`；彩色标注只用项目主题色（`#2563eb` 蓝、`#dc2626` 红、`#16a34a` 绿、`#ea580c` 橙、`#b45309` 琥珀、`#7c3aed` 紫、`#0f766e` 青） |
| 底色 | 一律不画白底：`fill="none"` / 半透明 `fill-opacity` / 剖面线 pattern |
| 线宽 | 粗实线 `stroke-width="2"`、细实线 `0.8`、虚线 `6 4`、点画线 `18 4 3 4`、双点画线 `20 4 3 4 3 4`、剖切位置线 `3` |
| 剖面线 | `<pattern>` 定义 45° / 135° 细实线，间距 6（另有间距 4 的加密版），`patternUnits="userSpaceOnUse"` |
| 文字 | `font-family="system-ui, sans-serif"`，字号 11 / 12 / 13；每块 `<text>` 都带 font-family（中文靠系统字体栈） |
| **id 命名空间** | 所有 defs 的 id 加图号前缀（`FIG-POUSHI-QUAN__hatch45`、`__ar-ink`）—— 同一页面并排嵌多张图时不会互相抢 pattern/marker（**这一条是实际踩到的坑**，见 §5.3） |
| 无障碍 | 每张带 `<title>` + `<desc>` + `role="img"` + `aria-labelledby` |
| viewBox | 按"真实内容包围盒 + 18 px 边距"**自动收紧**（原先画布留白太多，嵌进页面后字会缩得很小） |

## 4. 校验（必须做的那三项）

### 4.1 XML 合法性
用 `xml.dom.minidom.parseString()` 逐张解析。非法 XML 会直接抛异常，所以它同时能抓

写 `extra='stroke-width="1.4"'` 与线型类叠加就会重复；后来专门加了 `axis` 线型类解决。

## 5. 已知不足与踩过的坑

### 5.1 与任务书的两处有意不一致
1. **"k6 跨零线"** —— 按 GB/T 1800，k6 的 ei = +2 μm，公差带整体在零线上方，不跨零线。
   图按真值画，并在图注里点明（详见 §2.10）。如果教学上确实需要"跨零线"的样子，
   应换 `js6`（对称偏差）作例子，而不是 k6。
2. **"相邻零件的剖面线方向"** —— 任务书写的是"同一零件两个相邻剖视图"。国标的原话是
   **相邻两个零件**的剖面线方向应相反（同一零件各剖视图反而必须方向一致）。图按国标画，
   并在图注里把两条规则都写了。

### 5.2 这一轮改掉的版面问题（都是先截图才发现，纯看代码发现不了）
- `FIG-SANSHITU-EXAMPLE`：左侧"高度基准/长度基准"两个引注文字超出画布左边被裁；
  尺寸 20 与左视图挤在一起；"主视图"标签压在 40 的尺寸界线上。
- `FIG-POUSHI-BAN`：右侧注释文字超出画布被裁（已整体改为底部通栏）。
- `FIG-DUANMIAN`：图注与底部注释互相压字；"底板轮廓…"引注超出右边界。
- `FIG-GONGCHA-DAI`：两行"孔/轴公差带都在零线上方"的说明互相重叠；es/ei 与 Xmax 标签相邻太挤。
- `FIG-GONGCHA-PEIJIAN`：纵轴刻度数字被画布左边缘裁掉；配合结论文字压在轴公差带上。
- `FIG-LIUGESHITU`："仰视图"标签压住副标题。
- `FIG-POUMAINXIAN`：注释块缩进错位（x=200 改为 40）。
- `FIG-YUANHU-LIANJIE`：第 ③ 幅"画弧"仍留着直角尖角，与"擦掉多余线"矛盾（已改为完成状态）。

### 5.3 踩到的坑：多张 SVG 同页会互相抢 pattern / marker
最初所有图都用 `id="hatch45"`、`id="ar-ink"`。把 15 张内联进同一张预览页时，
**剖面线全部消失**（后面的图引用了第一张图同名但不在同一文档片段里的 pattern），
单张开却正常。已改为所有 defs id 加图号前缀（`FIG-XXX__hatch45`），复测同页 15 张剖面线全部正常。
> 前端如果要在一个页面/一个消息列表里同时渲染多张图，必须用这一版（已修好的）文件。

### 5.4 显示宽度的限制（前端需要注意）
图是按 11–13 px 字设计的，缩放会等比缩小字号：

| 容器宽度 | 11 px 字实际渲染 | 可读性 |
|---|---|---|
| ≥ 900 px | ≈ 10 px | 舒适 |
| 600 px | ≈ 7 px | 勉强，需放大 |
| 380–440 px（右侧栏） | ≈ 5 px | **不可读** |

建议：**放在主画布区/弹窗里按 ≥ 760 px 宽显示**，或提供"点击放大"；
右栏窄卡位只适合放缩略图 + 点击展开。这条已尽量通过收紧 viewBox 缓解（最窄的
`FIG-POUMAINXIAN` 是 623×494），但技术图本身信息量就大，靠缩字解决不了，只能给足宽度。

### 5.5 其他不足
- **不是 CAD 精度的工程图**：尺寸链、公差标注符合规范，但没有做真正的装配尺寸链计算；
  线宽用像素近似（粗 2 / 细 0.8），不是按 mm 比例换算。
- **中文依赖系统字体**：`system-ui` 在 Windows 上落到微软雅黑、macOS 上落到苹方；
  如果目标环境没有中文字体栈，中文会变方框。已在每块 `<text>` 上显式写 font-family 缓解。
- **`<img src>` 方式会把 `currentColor` 解析成黑色**：内联（React 组件/直接写进 DOM）时
  颜色跟随页面主题；用 `<img>` 引用时固定为黑，暗色页面需前端加
  `.figure svg { color: #e2e8f0 }`（内联）或对 `<img>` 用 `filter: invert()`。**推荐内联**。
- **图注未与后端接口打通**：`figures.jsonl` 目前是静态索引文件，还没接进 `/api`；
  前端要用需要加一个读取接口（本次任务不改 `apps/`、`pipeline/`，故未动）。
- **没有成对图/差异标注**（`kb/figures/pairs/`，docs/04 里的 T27 任务），本次未做。
- **轴测图、相贯线、齿轮啮合、键/销/轴承**等章节还没有配图，15 张只覆盖了第一、三、五、七、八、九章。

## 6. `_tools/` 是什么（不属于产品，可删）

这些图不是手写 SVG 文本，而是用一套小程序生成的 —— 因为三视图必须**几何严格对齐**、
公差图数值必须能和引擎对上，手敲坐标很容易错。源码留档，方便以后加图或改尺寸：

| 文件 | 作用 |
|---|---|
| `svgkit.py` | 迷你 SVG 工具箱：线型类、箭头 marker、剖面线 pattern、波浪线、圆弧取样、尺寸/引线、包围盒自动统计 |
| `figs_a.py` | 图 1–4（线型、三视图形成、组合体、六视图） |
| `figs_b.py` | 图 5–9（全剖、半剖、局部剖、断面、剖面线方向） |
| `figs_c.py` | 图 10–15（公差带、圆弧连接、螺纹、表面结构、尺寸四要素、三种配合） |
| `catalog.py` | `figures.jsonl` 的唯一数据源（图号、标题、章节、kp_id、图注…） |
| `build.py` | 生成 15 个 SVG + `figures.jsonl`，并跑全部校验、打印上表 |
| `check_tolerance_values.py` | 调 `apps/api/app/domain/tolerance.py` 核对公差数值（只读，不改 apps） |
| `make_preview.py` | 生成 `preview_all.html` / `preview_one.html` 两张人工检查页 |
| `_s_*.png` / `_r_*.png` / `_dark_quan.png` / `_final_all.png` | 渲染验证截图留档 |

**重新生成**（改完 `catalog.py` 或任一 `figs_*.py` 后）：

```powershell
cd D:\桌面\机械制图agent
D:\python\python.exe kb\figures\_tools\build.py          # 重建 + 校验（0 错误才算过）
D:\python\python.exe kb\figures\_tools\make_preview.py   # 重建人工检查页
D:\python\python.exe kb\figures\_tools\check_tolerance_values.py   # 复核公差数值
```

> 与知识库构建的关系：`apps/api/app/rag/chunking.py` 的 `load_kb()` 只扫 `kb/**/*.md`
> （且跳过 README）、`kb/knowledge/kp.jsonl`、`kb/exercises/*.jsonl` 三处，
> 所以新增的 `kb/figures/figures.jsonl`、`*.svg`、`_tools/*.py` **不会被卷进检索索引**，
> 对现有 KB 行为和评测没有影响 —— 这一点是读源码确认过的，不是推测。
