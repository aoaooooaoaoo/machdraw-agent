## 1. 数据格式

```json
{"source": "Q-002", "target": "Q-012", "relation": "prereq", "why": "补第三视图全靠长对正、高平齐、宽相等逐块投影"}
```

| 字段 | 说明 |
|---|---|
| `source` / `target` | `questions.jsonl` 中真实存在的 `qid`，方向为"先 source 后 target" |
| `relation` | 只取 `prereq`（前置依赖）/ `contrast`（对比辨析）/ `compose`（组成）/ `cause`（因果），与知识图谱 `edges.jsonl` 的 `rel` 同一套词汇 |
| `why` | 一句话说明为什么连这条边，**必须点到具体知识点**（不写"两题相关"这类空话），供教师端与学情推送直接复用 |

前端约定建议：
- `prereq` 画实线箭头、`contrast` 画虚线（对比关系本身无方向语义，可按无向渲染，数据里的 source→target 只为保持 DAG）、`cause` 画带因果关系强调色的箭头；
- 上下游高亮直接在这个 DAG 上做有向 BFS（无环，不会死循环）。

## 3. 设计思路

### 3.1 为什么必须人工写，不能靠"共享知识点"派生

实测过按 `kp_ids` 交集派生：L1→L2 只有 2 条、L2→L3 为 0 条。原因是三层题目**刻意不共用知识点**——L1 考单点记忆（幅面、五要素、公差等级），L2 考方法应用（补视图、配合计算、剖视选型），L3 考跨章综合（表达方案、拆画、公差选择）。三层之间是**认知层级的递进**，不是同一知识点的重复出现，所以问题链只能按"学完这一步才做得动下一步"的认知依赖手工建立。

### 3.2 连边判据（三条，按优先级）

1. **知识点前置**：目标题某个 `kp_id` 的前置知识点，正好是源题的考点。例：Q-012 的 kp 是"读图步骤/形体分析/补第三视图"，其前置是"三等规律"（Q-002）；Q-020 的 kp 含"零件表达方案/剖视概念/主视图选择"，其前置是"剖视选型"（Q-015）、"六基本视图"（Q-010）。
2. **解题步骤依赖**：目标题的作答过程必须先用源题的结论。例：Q-021 拆画泵体要"移注配合尺寸并把代号换成极限偏差"，必须先会 Q-014 的配合计算；Q-024 要综合处理"截切 + 正交相贯"，必须先会 Q-019 的简化圆弧。
3. **易错点因果**：源题的规则是目标题某个"特殊规定"的由来。例：Q-003（剖面线规则）→ Q-016（肋板纵剖不画剖面线）用 `cause`，因为"肋板按不剖画"正是对剖面线规则的例外设定；Q-013（共面/相切）→ Q-022（不注交线尺寸）也用 `cause`，因为"相切处不画线"与"相切处不注尺寸"同源。

### 3.3 骨架与汇聚点

- **L1 是发源层**：11 道 L1 题里有 10 道只有出边（Q-008 例外，它通过同层对比边被 Q-002 指向），出度合计 15，符合"基础概念先学、向下供给"。
- **L2 是转换层**：入度 8、出度 11，起到"方法技能 → 综合任务"的桥接作用。
- **L3 是汇聚层**：入度 18、出度 1，7 道 L3 里有 6 道是终点。其中 **Q-020（支架表达方案）入度 6**，是全图最大汇聚点，对应"表达方案"在课程中的枢纽地位；**Q-021（拆画零件图）** 收 3 条入边，是整条链的最终出口（"表达方案 → 拆图"）。
- 最长链 4 条边：`Q-004（半剖分界）→ Q-015（剖视选型）→ Q-017（断面 vs 剖视）→ Q-020（表达方案）→ Q-021（拆画）`，正好是一条完整的"剖视规定 → 选型 → 方案 → 拆图"能力链，可直接用作页面默认高亮的示例路径。

### 3.4 同层对比只放 3 条的理由

同层边全部用 `contrast`，选的是三组真正会混的题，而不是凑数：
- **Q-002 ↔ Q-008**：三视图（度量性好、要想象）↔ 轴测图（直观、不能直接量取），是第六章开篇必讲的对比；
- **Q-015 ↔ Q-017**：都是在"选表达方法"，但一个在剖视种类里选、一个在断面与剖视之间选，学生最容易串；
- **Q-020 ↔ Q-021**：都是"表达方案"任务，但一个是自建设计、一个是在装配图约束下重构，方法迁移时最易照抄。

### 3.5 为什么没有用 `compose`

`compose`（组成/包含）适合"整体—部分"结构（如知识图谱里"剖视图包含剖面线"）。这批 26 道题是按**学习阶段 + 任务类型**组织的，不存在天然的"整体题包含部分题"关系；硬造 compose（例如把 Q-022 拆成"定形尺寸题/定位尺寸题"）会引入不存在的题目结构，故本批不设 compose 边。若后续按知识点补"部分题"（如单独出"定形尺寸怎么注"），可再补 compose。

| 5 | **Q-002 → Q-008**（三等规律 → 正等测，同层 contrast） | 两题知识点没有依赖，只有"直观性 vs 度量性"这一层对比；方向性也弱（对比本身无向） | 保留（这是课程里真实存在的对比讲法），前端按无向虚线渲染即可 |

另有一处**结构上的取舍**需要说明：Q-018（多线漏线）只入不出，是 L2 的"终端题"。本来可以再加 `Q-018 → Q-020`（视图自检清单服务于表达方案），但 Q-020 的入边已经 6 条，再加会让页面在 Q-020 处过度拥挤，故未连；Q-018 通过 Q-002 的入边仍被点亮。

## 6. 使用与维护约定

1. **只增不改**：本次只新建 `kb/graph/question_edges.jsonl`，未改动 `questions.jsonl` / `nodes.jsonl` / `edges.jsonl`。
2. **加题时补边**：若在 `questions.jsonl` 追加题目，必须同步给新题至少连 1 条边，并重跑 `_check_question_edges.py`（孤岛与无环两项会自动把关）。
3. **边的方向即学习顺序**：`source` 是先学的题。`contrast` 边虽然语义无向，但数据里仍按"较基础的题 → 较进阶的题"定向，以保持 DAG；前端渲染时可当作无向线。
4. **`why` 是可复用资产**：它会被教师端"为什么推荐先做这题"与学情推送直接引用，改边时务必同步改 `why`，不要留下与考点不符的说明。
5. **规模上限**：22–30 条是评审给出的舒适区；若后续题目扩充到 40+，建议控制在"题目数 × 1.1"以内，避免页面连线糊成一团。
