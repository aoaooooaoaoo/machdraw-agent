`ChatMessage`（`types.ts:58-71`）：`{id, role:'user'|'assistant'|'system', content, thinking, tools:ToolCallState[], artifact?, streaming, error?, meta?:DoneMeta, frames}`。
`ToolCallState`（`:34-42`）：`{id,name,label,args,status:'running'|'done'|'error',summary,detail}`。
`role:'system'` 是**前端追加的提示**（如"该产物类型暂无画布"），`send()` 时会被过滤掉不发后端（`store.ts:412-415`）。

| 行为 | 实现 | 行号 |
|---|---|---|
| bootstrap 幂等 | `if (bootstrapping \|\| bootstrapped) return`（React 19 StrictMode 会跑两遍） | `:308` |
| 并发取 health + modules | `Promise.allSettled`，modules 失败不阻塞 | `:312-329` |
| 默认模块回落 | 当前 feature 不在 modules 列表里 → 取第一个 | `:318-323` |

### 6.5 SSE 解析器（`lib/sse.ts` 221 行）——五条容错逐条对应代码

| # | 容错要求 | 实现 | 行号 |
|---|---|---|---|
| 1 | 帧间可能夹不带 `data:` 前缀的进度行（如 `{"revision":2}`）→ 跳过不崩 | `extractData()` 只收 `data:` 行，其余 `onSkip(line,'no-data-prefix')` | `:46-59` |
| 2 | 网络分片可能切在 UTF-8 多字节中间 | `new TextDecoder('utf-8')` + `decode(value,{stream:true})` 累积，流末尾再 `decode()` 冲一次 | `:127`、`:163`、`:181` |
| 3 | 单帧 JSON 解析失败 → 跳过并计数，不让整个对话失败 | `try/catch` → `stats.dropped += 1` | `:141-153` |
| 4 | 服务端可能不发结尾空行 | 循环结束后把 `buffer.trim()` 剩余内容再 `handleBlock` 一次 | `:180-187` |
| 5 | 收到 `[DONE]` 立即停止并 `cancel` reader | `handleBlock` 返回 true → `stats.outcome='done'` + `reader.cancel()` | `:139`、`:171-176` |

其它协议细节：
- `data:` 后允许有无空格（`trimData`，`:40-43`）；
- 统一 `\r\n`→`\n` 后按 `""`（空行）切块（`:166-170`）；
- 多行 `data:` 用 `\n` 拼接（规范兼容，本项目不用）；
- `ChatHTTPError`（带 status+body）与 `extractErrorMessage`（`detail > message > error > 原文`，兼容 FastAPI 422 的 detail 数组）（`:61-93`）；
- `parseSSEText(text)` 纯函数版本，供单测/离线回放（`:203-221`）。

`streamChat` 的请求头（`:104-111`）：`Content-Type: application/json`、`Accept: text/event-stream`、`X-Account: <account>`。

## 9. 评测 harness 与 tests 清单

### 9.1 探针文件（`eval/probes.jsonl` 56 行 = 54 题 + 2 空行 / `eval/probes_holdout.jsonl` 38 行 = 38 题）

一行一题，schema 只有 4 个字段：

```json
{"id":"P01","domain":"in","q":"三视图的投影规律是什么？","expect_docs":["视图与三视图"]}
{"id":"P02","domain":"in","q":"俯视图和左视图应该放在什么位置？","expect_docs":["视图与三视图"]}
```
- `domain ∈ {in, out, near}`：课内 / 课外（必须拒答）/ 边缘（只报告不判对，见 `run.py:73`）；
  - 标定集实测分布：`in=38 / out=15 / near=1`（54 题）；
  - held-out 实测分布：`in=30 / out=8`（38 题），与 README 的"课内 29/30、课外 8/8"一致；
- `expect_docs`：期望命中的文档标题**子串**，用于算 `doc_hit`（不进 acc）；
- 以 `#` 开头的行会被跳过（`run.py:31`；旧集里实际没有注释行）。

### 9.2 `eval/run.py`（138 行）指标口径

判对标准（`run.py:48-52`）——**只判"该拒的拒、该答的答"，不判答案质量**：

```python
if p["domain"] == "out":  ok = gated        # 课外必须被门控
else:                     ok = not gated    # 课内(含 near)必须不被门控
```

输出的指标（`evaluate()`，`run.py:65-76`）：

| 指标 | 定义 |
|---|---|
| `acc` | `ok` 数 / 总题数 |
| `in_min` | 课内题 coverage 的最小值 |
| `out_max` | 课外题 coverage 的最大值 |
| `separation` | `in_min - out_max`（**分离带**，越大门控越干净） |
| `in_recall` | `课内未被门控 / 课内总数`（字符串 `a/b`） |
| `out_reject` | `课外被门控 / 课外总数` |
| `near_note` | near 域未被门控数（仅参考） |
| `doc_hit` | 课内题中 `expect_docs` 任一命中 top5 文档的比例 |
| `rows` | 逐题：`{id,domain,q,coverage,gated,ok,doc_hit,top}` |

三种运行方式（`run.py:79-134`）：
- `python eval/run.py`：默认 `τ=0.55, λ=0.45`，逐题打印表；
- `--sweep`：`λ ∈ {0.30,0.35,0.45,0.55} × τ ∈ {0.30,0.35,0.40,0.45,0.50,0.55}` 网格，按 `(acc, separation)` 取最优（`:104-115`）；
- `--write`：结果落到 `eval/results/run-YYYYmmdd-HHMMSS.json`（`:127-133`）；已有 4 个结果文件 + `holdout-38probes.json` 作为证据留存。
- 另有 `--probes <文件名>` / `--tau` / `--lam` / `--tau-chunk` 参数。

> 重要：`run.py` 直接 `load_kb()` + `build_index()` **现建索引**（不读 data/index），所以评测永远与被测 kb 一致（`run.py:93-97`）。

### 10.1 `Dockerfile`（49 行，两阶段）

```dockerfile
# 阶段 1：node:22-alpine 构建前端
FROM node:22-alpine AS web
WORKDIR /web
COPY apps/web/package.json apps/web/package-lock.json* ./
RUN npm ci --no-audit --no-fund || npm install --no-audit --no-fund
COPY apps/web/ ./
RUN npm run build                     # → /web/dist

# 阶段 2：python:3.12-slim 运行时
FROM python:3.12-slim
WORKDIR /app
ENV PYTHONUNBUFFERED=1 PYTHONIOENCODING=utf-8 MW_LLM_PROVIDER=mock
COPY apps/api/requirements.txt ./requirements.txt
RUN pip install --no-cache-dir -r requirements.txt
COPY apps/api/app ./apps/api/app
COPY apps/api/tests ./apps/api/tests
COPY apps/api/static ./apps/api/static
COPY pipeline ./pipeline
COPY kb ./kb
COPY eval ./eval
COPY --from=web /web/dist ./apps/web/dist
RUN python pipeline/build_kb.py        # 镜像内预建索引（2–5s）
RUN mkdir -p /app/data
VOLUME ["/app/data"]                   # SQLite 落盘（平台多为临时盘，重启重置）
EXPOSE 8077
HEALTHCHECK --interval=30s --timeout=5s --start-period=25s --retries=3 \
  CMD python -c "…urlopen('http://127.0.0.1:'+os.environ.get('PORT','8077')+'/api/health')…"
CMD ["sh", "-c", "exec uvicorn app.main:app --host 0.0.0.0 --port ${PORT:-8077} --app-dir apps/api"]
```

三个必须理解的细节：
1. **`--app-dir apps/api`**：因为 `main.py` 用 `from .config import …`（相对导入），uvicorn 必须以 `apps/api` 为 import 根，模块名是 `app.main:app`；
2. **`sh -c` 才能展开 `${PORT}`**（exec 形式不展开环境变量，`Dockerfile:48` 注释写明）；
3. **索引在镜像里预建**：容器启动不做切分，`load_state()` 直接 `Index.load`；这也意味着**改了 `kb/` 必须重建镜像**（或运行时 `POST /api/admin/reload` 触发重建）。
