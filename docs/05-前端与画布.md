## 1. 技术栈与目录结构

### 1.1 技术栈

| 层 | 选型 | 说明 |
|---|---|---|
| 框架 | React 19 + TypeScript 5.7 + Vite 6 | 三栏壳 + 画布自注册；`jsx: react-jsx`，`strict: true` |
| 样式 | 原生 CSS 单文件 `src/app.css` | 不引 Tailwind/AntD；CSS 变量作设计令牌（`--bg/--panel/--border/--text-*/--accent/--mono/--shadow-sm`） |

| 流式 | `fetch` + `ReadableStream` | `/api/chat` 是 POST（带 body + `X-Account`），`EventSource` 只能 GET，故不用 |

| 图表 | **纯 SVG，无图表库** | `modules/plot/chart.ts` 负责刻度/坐标映射，React 只摆 SVG 元素 |
| 依赖 | `react` `react-dom` `zustand` `marked` | 构建期 `typescript` `vite` `@vitejs/plugin-react` `@types/*`；无全局安装 |

## 2. 三栏壳与数据流

### 2.1 启动与登录

1. `App.tsx` 挂载后调用 `store.bootstrap()`（幂等保护：`bootstrapping/bootstrapped`）。
2. 并行执行：
   - `getHealth()` → `GET /api/health`，得到 `HealthInfo`（tools/chunks/docs/nodes/edges/sparse_weight/gate_tau/warnings），失败则 `backendOnline=false`；
   - `getModules()` → `GET /api/modules`，得到模块清单；若当前 `activeFeature` 不在清单里，回落到 `modules[0].id`。
3. 账号存在 `localStorage['rp.account']`；无账号时渲染 `<LoginGate/>`，登录走 `POST /api/auth/login`（后端首次输入自动建号），成功后写回 localStorage 并刷新 health。
4. 顶部连接状态 chip 显示 已连接/未连接/检测中；未连接时可点击重试。

### 2.2 三栏布局

```
顶栏 56px：产品名 | 账号 | 模型标识 | 连接状态 | 意见反馈
──────────────────────────────────────────────────────────
左栏 220px │ 中栏自适应 │ 右栏 clamp(380px, 30vw, 440px)
            │            │
状态栏 34px：N 条消息 · 证据 M 段 · 覆盖率 X% · 耗时 T ms · 帧 N
```

- 左栏收窄：`≤1120px` 变 68px 图标栏；右栏 `≤1240px` 360、`≤940px` 320；`≤820px` 画布下沉为第二行（不参与侧边收起）。
- 右栏可手动收起：`CanvasPanel` 把 `.workbench` 的 `--right-w` 压成 48px；恢复时清内联变量。

### 2.3 一次问答的完整数据流

```
用户 Composer 输入
  └─ store.send(text)
       ├─ 追加 user 消息 + 空 assistant 消息（streaming=true），清空本轮 artifacts/stats
       ├─ 组装 feature 身份：modules.find(activeFeature) → {id,name,persona}
       ├─ POST /api/chat {session_id:`local:${featureId}`, messages, feature}
       └─ streamChat(body, {account, signal, onEvent})
            └─ SSE 逐帧 → store.applyEvent(featureId, assistantMsgId, ev)
                 ├─ thinking/token        → 追加思考块/正文
                 ├─ tool_call             → 新增工具卡（running）
                 ├─ tool_result           → 按 id 回填 done + summary/detail
                 ├─ artifact              → hasCanvasOwner 校验后 push 到 artifacts（保留最近 8 个）
                 ├─ error                 → 消息内错误 + streaming=false
                 └─ done                  → 写 ms/evidence/coverage，收尾统计
```

- 历史过滤：只发 `user/assistant` 且非"空 assistant"消息（前端追加的 `system` 提示不发给后端）。
- 中断：`store.stop()` abort 当前 `AbortController`，消息显示"已手动停止生成"。
- 未知 `artifactType`：不入画布、不静默丢弃，在中栏补一条系统提示，方便定位"工具类型写错 / feature 未注册"。

### 2.4 store 状态机关键字段（`lib/store.ts`）

| 字段 | 类型 | 说明 |
|---|---|---|
| `account` | `string \| null` | 登录账号；localStorage key `rp.account` |
| `backendOnline` | `boolean \| null` | null=检测中；false 时状态栏/顶栏显示离线 |
| `health` | `HealthInfo \| null` | `/api/health` 结果（工具、知识库规模、门控 τ） |
| `modules` / `modulesError` | `ModuleManifest[]` / `string \| null` | 后端模块清单（九个模块）与加载错误 |
| `bootstrapped/bootstrapping` | boolean | 启动幂等保护 |
| `activeFeature` | `string` | 当前模块 id；默认 `__global__`（全局对话） |
| `sessions` | `Record<string, SessionState>` | **按模块分片**的会话；切模块不丢历史 |
| `globalError` | `string \| null` | 全局错误条（如未登录提问） |

`SessionState`：

| 字段 | 说明 |
|---|---|
| `id` | 会话 id（`local:<feature>`） |
| `messages` | `ChatMessage[]`（含 `thinking/tools/artifact/streaming/error/meta/frames`） |
| `artifacts` | 本轮收到的画布，按到达顺序；`slice(-8)` 上限 8 个 |
| `stats` | `{messages, evidences, coverage, ms, frames}` |
| `draft` | 中栏输入框草稿（画布"追问"按钮写这里） |
| `streaming` | 是否生成中 |

派生选择器 `useActiveSession()` 返回当前模块会话；模块级 `FALLBACK_SESSION` 保证 Zustand v5 的 `useSyncExternalStore` 快照稳定（避免无限重渲染）。

### 2.5 SSE 帧处理（`lib/sse.ts`）

| type | 处理 |
|---|---|
| `thinking` | 追加到该消息思考块（可折叠、显示字数） |
| `token` | 追加正文，末尾流式光标 `▍` |
| `tool_call` | 新增工具卡（`label/name/args`，running） |
| `tool_result` | 按 `id` 回填（done + `summary/detail`）；无对应 call 时补一张结果卡 |
| `artifact` | 校验 owner 后挂到本轮画布；右栏开标签页 |
| `error` | 消息内红色错误块 + 结束流式 |
| `done` | 写 `data.ms/evidence/coverage`，状态栏收尾；`[DONE]` 后 cancel reader |

容错：跳过不带 `data:` 的进度行；`TextDecoder` 缓冲处理 UTF-8 多字节截断；单帧坏 JSON 跳过并计数；HTTP 非 2xx 提取 FastAPI `detail`。

### 2.6 右栏画布分发与标签页（`shell/CanvasPanel.tsx`）

```
session.artifacts（本轮全部画布）
  ├─ 无 artifact → 空态
  │    ├─ 模块声明 canvas_kinds（来自 /api/modules）
  │    ├─ 每个 kind 查 registry.getPreview(type) → 「查看…示例」按钮
  │    └─ 空态提示已实现渲染器数量（KNOWN_CANVAS_TYPES 减去 placeholder）
  ├─ 有 artifact → 默认选中最后一个；多个时显示标签页（title 来自 registry）
  ├─ 示例查看中：demoArtifact 挂到 preview.data，画布带「示例数据」标记
  ├─ graph 模块无 artifact → 额外构造 entryArtifact（全览星图入口，标「全览入口」）
  └─ 自动展开：shouldAutoOpen(latestArtifactType) 时取消收起
```

- 画布标题/副标题/示例/自动展开**全部走 registry**，壳不写死任何 artifactType。
- 切换模块时：清空示例；按该模块 `canvas_kinds` 中是否有 `autoOpenCanvas=true` 的画布决定初始开合（全局对话默认展开）。

### 2.7 整页模式（graph）

`App.tsx` 查 `getCanvasFeature(activeFeature)?.page`；有 `page` 时主区整体让给它（`gridColumn: 2 / -1`），左栏保留作退出出口，并向 Page 注入 `messages/busy/onSendMessage`。目前只有 `features/graph/index.ts` 声明了 `page: GraphPage`（全览星图 + 问题图谱 + Agent 抽屉）。

### 3.2 `calc` · 确定性计算卡

- **组件**：`modules/calc/Canvas.tsx`（替代旧 `tolerance` 画布）
- **data 契约**（`CalcData`，SPEC §4.1）：

```jsonc
{
  "title": "裸圆柱堆次临界校核（单群扩散）",
  "inputs":   [{ "name": "无限增殖因数 k∞", "value": 1.06, "unit": "—" }],
  "formulas": [{ "step": "M² = L² + τ = 100 + 80 = 180 cm²", "note": "徙动面积" }],
  "results":  [{ "name": "有效增殖因数 k_eff", "value": 0.893, "unit": "—", "note": "k_eff < 1 → 次临界" }],
  "verdict":  { "level": "次临界", "note": "Bg² > Bm²，泄漏大于增殖…" },
  "refs":     ["教材 第四章 4.2 节"],
  "note":     "假设：单群扩散、裸圆柱 R = H/2…",
  "svg":      "<svg …>…</svg>"   // 可选，后端预渲染
}
```

- **渲染顺序**：标题 → 输入表（量/取值/单位）→ 计算步骤（`formulas` 逐条编号，公式用等宽字体 + 行内说明）→ 结果表（量/数值/单位/说明）→ 结论条（`verdict.level` + `note`，按关键词自动配色）→ 依据（`refs` chip）→ 可选 `note` → 可选 `svg`。
- **结论条配色**：`verdictTone()` 先判「次临界/亚临界/不合格/不满足」→ 蓝；再判「超临界/超限」→ 红；普通「临界/满足/合格」→ 绿；其它中性。
- **数值格式**：`number` 按量级格式化 —— 常规量级 4 位小数去尾零；很小/很大用 `a×10ⁿ`（Unicode 上标，如 `3.33×10⁻⁴`），避免右栏出现 `3.33e-4`。
- **demo**：`CALC_DEMO_DATA`，裸圆柱堆次临界校核，见 §4.3。

## 4. `calc` / `plot` 两个新画布的实现要点

### 4.1 `calc`：从"公差不带"到"计算卡"

旧工程 `tolerance` 画布是机械制图专属（孔/轴偏差 + 公差带图），本工程整体替换为通用的**确定性计算卡**：

| 区块 | 实现 | 样式 |
|---|---|---|
| 标题 | `data.title` + artifactType chip + 「示例」chip | `.calc-head/.calc-title` |
| 输入表 | `inputs[{name,value,unit}]`，三列 | 复用 `.tol-table-wrap/.tol-table` |
| 计算步骤 | `formulas[{step,note}]`，`<ol>` 逐条编号，公式等宽 | `.calc-formulas/.calc-formula/.calc-formula-code` |
| 结果表 | `results[{name,value,unit,note}]`，四列 | 复用 `.tol-table` |
| 结论条 | `verdict.level` + `note`，关键词判色 | `.calc-verdict.is-ok/.is-under/.is-over/.is-neutral` |
| 依据 | `refs[]` → chip | 复用 `.chip-doc` |
| 说明 | `note` | 复用 `.tol-note` |
| 图示 | 可选 `svg`，`dangerouslySetInnerHTML` | `.calc-svg` |

- 空/缺字段兜底：没有输入/公式/结果/结论/svg 时显示"calc artifact 还没有…" + JSON 片段，不白屏。
- 兼容 `burnup_calc` / `reactivity_calc` / `critical_calc` 等所有"输入 → 公式 → 结果"型工具；`verdict.level` 不限于临界语义（含"满足/不合格"等关键词也能判色）。

### 4.2 `plot`：纯 SVG 折线图（无图表库）

**几何计算全部在 `modules/plot/chart.ts`（纯函数、可单测）：**

| 函数 | 作用 |
|---|---|
| `niceStep(raw)` | 1/2/5/10 × 10ⁿ 的"好看"步长 |
| `linearTicks(min,max,target)` | 线性轴：向外取整到步长整数倍，首末刻度落在轴端；数据非负时不画 0 以下空白 |
| `logTicks(min,max)` | log10 轴：整十次幂刻度；跨度 ≤3 个数量级时补 2/5 倍；刻度不足 2 个时回落两端点 |
| `tickLabel(v,isLog)` | log 轴写 `10⁻³` 等 Unicode 上标；线性轴按量级取舍 |
| `buildPlotGeometry(data,w,h)` | 汇总：清洗 points（有限、按 x 排序）、判定 log 轴、计算绘图区/刻度/像素坐标/折线 `path`/markers，输出可直接渲染的 `PlotGeometry` |

**log 轴判定**：`kind === 'spectrum'` 或 `xMax/xMin ≥ 100`，且 `xMin > 0`（否则回落线性轴，避免 log(0)）。

**渲染层（`modules/plot/Canvas.tsx`）**：`useId` 生成唯一 `clipPath` id（内联与弹层各一份，避免 ID 冲突）；曲线用 `<path d="M…L…">` + `vectorEffect="non-scaling-stroke"`，裁剪在绘图区内；markers 竖虚线画在曲线下；放大弹层直接复用同一份 `PlotGeometry`（不重算），只放大 viewBox 显示尺寸。

**落区校验**：无头校验脚本对 demo 的 91 个点逐一断言 `left ≤ x ≤ right`、`top ≤ y ≤ bottom`，全部通过（见 §6.3）。

### 4.3 两处数值口径说明（demo 自洽性）

> 原则：demo 是**示例数据**，必须内部自洽、公式可复算，并在画布 `note`/源码注释里写明假设；不为了凑任务书数字而伪造物理。

#### calc demo：裸圆柱堆次临界校核（单群扩散）

输入：`k∞ = 1.06`、`L² = 100 cm²`、`τ = 80 cm²`、裸圆柱取 `R = H/2 = 89.1 cm`（`H = 178.2 cm`）。

```
M²  = L² + τ                        = 180 cm²
Bm² = (k∞ − 1) / M²                 = 3.333×10⁻⁴ cm⁻²     （材料曲率）
Bg² = (2.405/R)² + (π/H)²           = 1.039×10⁻³ cm⁻²     （裸圆柱几何曲率）
k_eff = k∞ / (1 + M²·Bg²)
      = 1.06 / (1 + 180×1.039×10⁻³)
      = 1.06 / 1.187 = 0.893  < 1      → 次临界
R_c = √(8.2505 / Bm²) ≈ 157.3 cm（H_c ≈ 314.7 cm）
```

- 结论条：`level = 次临界`，`note` 说明 `Bg² > Bm²`、泄漏大于增殖，需增大尺寸/加反射层/提高富集度。
- **口径偏差（重要）**：任务书给的 `Bm² = 6.67×10⁻⁴` 与 `k_eff = 0.893` 在单群公式下**不能同时成立**——`k_eff = k∞/(1+M²B²)` 在 `M²=180` 时只允许一个 `B²`（`k_eff=0.893` 要求 `B²≈1.04×10⁻³`）。demo 取**自洽解**（M²=180 / Bm²=3.33×10⁻⁴ / Bg²=1.04×10⁻³ / k_eff=0.893）；若把 `R` 放大到 `111.2 cm`，则 `Bg² ≈ 6.67×10⁻⁴`、`k_eff ≈ 0.946`，仍次临界。该说明同时写在 `modules/calc/demo.ts` 注释与 `apps/web/README.md`。
- `refs`：`["教材 第四章 4.2 节"]`。

#### plot demo：点堆阶跃响应（ρ = +0.2$）

输入：`ρ = +0.2$ = 0.2β = 0.0013`、`β = 0.0065`、瞬发中子寿命 `ℓ = 1e-4 s`、单组缓发中子衰变常数 `λ = 0.0784 s⁻¹`；初始稳态 `n/n₀ = 1`，`t=0` 施加正阶跃。

解单组缓发中子点堆方程：

```
dn/dt = (ρ − β)/ℓ · n + λc
dc/dt = β/ℓ · n − λc

特征方程：ℓω² + (β − ρ + λℓ)ω − λρ = 0
n(t)/n₀ = A·e^{ω₁t} + B·e^{ω₂t}
A + B = 1，c(0) 取稳态值 βn₀/(λℓ)
```

结果：`t→0⁺` 瞬跳比 `β/(β−ρ) ≈ 1.25`；渐近周期 `T = 1/ω₁ ≈ 51 s`；`t = 20 s` 时 `n/n₀ ≈ 1.84`；生成 **91 个点**（0~0.02 s 用 0.002 s 细步长抓瞬跳，0.05~20 s 用 0.25 s 步长）。

- **口径偏差（重要）**：任务书写"0~20 s 从 1 跳到约 11"，这对应约 **+0.5$** 的反应性；按给定的 `+0.2$` 如实计算只能到 `1.84`。demo 选择**忠实于给定输入**并保持物理自洽，源码注释与 README 已写明；若需要"20 s≈11"的画面，应把输入改为 `ρ=+0.5$`（由 Lead/教学口径决定，不擅自改）。
- `refs`：`["教材 第八章 8.2 节"]`；`note` 标明"单组缓发中子近似、未计温度反馈与六组缓发中子结构"。

## 5. 自注册机制（`features/*/index.ts`）

### 5.1 `CanvasFeature` 契约（`lib/canvasFeature.ts`）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | string | ✅ | **必须等于 `features/` 下的目录名**；registry 校验不一致就跳过并 warn |
| `title` | string | ✅ | 画布标题（右栏 `<h2>` / 标签页 title），壳不写死 |
| `hint` | string | ✅ | 画布副标题/提示 |
| `artifactTypes` | string[] | ✅ | 该 feature 认领的 artifactType，**全局唯一**（重复 warn，后注册覆盖） |
| `order` | number | ✅ | 列表排序，决定 `KNOWN_CANVAS_TYPES` 顺序（当前 = SPEC §4.1 顺序） |
| `preview` | `{label,data}` | 可选 | 空态「查看…示例」按钮；`data` 直接作为 `artifact.data` 喂给组件 |
| `autoOpenCanvas` | boolean | 可选 | 产出该类型时是否自动展开右栏；展示型 true、对话型 false |
| `Component` | React 组件 | ✅ | 画布模式组件（右栏），props 为 `FeatureProps` |
| `page` | React 组件 | 可选 | 整页模式；填了它，左栏点该模块时主区整体让给它（目前只有 graph） |

`FeatureProps`：`{ artifact, onAsk, demo?, messages?, busy?, onSendMessage? }`。画布只读 `artifact.data`，通过 `onAsk` 把追问写回中栏草稿。

### 5.2 registry 扫描与校验（`modules/registry.ts`）

```ts
const modules = import.meta.glob<{ default: CanvasFeature }>('../features/*/index.ts', { eager: true });
// 校验：有默认导出、id === 目录名、artifactTypes 非空；按 order 升序
// 派生：
//   REGISTRY[artifactType] = { title, hint, component }
//   PREVIEWS[feature.id|artifactType] = preview
//   PREVIEW_TYPES[feature.id] = artifactTypes[0]
//   AUTO_OPEN[artifactType] = autoOpenCanvas
```

导出 API：`getCanvasDef`（未知类型回落 `PlaceholderCanvas`）、`getPreview`、`getPreviewType`、`shouldAutoOpen`、`isPlaceholder`、`hasCanvasOwner`（store 兜底未知 artifact）、`KNOWN_CANVAS_TYPES`、`CANVAS_FEATURES`、`getCanvasFeature`。

### 5.3 新增一个画布的步骤

1. 新建 `src/features/<id>/index.ts`，`id` 必须等于目录名，声明 `title/hint/artifactTypes/order/Component`，需要示例就加 `preview`。
2. 新建 `src/modules/<id>/Canvas.tsx`（如需本地示例再加 `demo.ts`），props 用 `CanvasProps`（= `FeatureProps`）。
3. 确认 `artifactTypes: ['<id>']` 与 `id` 一致；`order` 插到合理位置（不改 registry）。
4. 若需要整页模式，加 `page` 组件；若需要空态示例，加 `preview`。
5. `npm run typecheck && npm run build`；启动后空态点示例即可验证（demo 会带「示例数据」标记）。
6. 后端工具产出的 `artifact_type` 必须与 `artifactTypes` 完全一致，否则 store 会补"该产物类型暂无画布"提示。

5. **意见反馈仅本地**：写 `localStorage['rp.feedback']`，无后端接口。

7. **断线不自动重连**：健康检查失败只改状态显示；流式请求失败在消息内显示错误，下次提问重试。

9. **公式不渲染**：`calc.formulas.step` 只用等宽字体呈现公式文本。

### 7.5 常见排障

| 现象 | 排查 |
|---|---|
| 页面「后端未连接」 | 后端未起/端口不是 8077；看 `vite.config.ts` 代理 target 与后端日志 |
| 画布标题是 `xxx 画布` + "尚未在注册表中登记" | 后端 `artifact_type` 与 feature `artifactTypes` 不一致，或 `features/<id>/index.ts` 的 `id` 与目录名不一致（registry 会 warn） |
| 空态没有「查看示例」 | 该 feature 未声明 `preview`（evidence/annotation/wrongbook/graph 本就没有本地 demo） |
| comparison 图片 404 | `kb/figures/pairs/PAIR-SPECTRUM.svg` 未生成，或后端未挂 `/figures` 静态路由 |
| `npm run build` 报 TS 错 | 先 `npm run typecheck` 看具体文件；契约改动先改 `lib/types.ts` 与 SPEC |
