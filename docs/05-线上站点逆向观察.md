# 05 · 线上站点逆向观察（materials-lab-agent.onrender.com）

> 观察时间：2026-11-07
> 方法：公开访问 + 前端 bundle 静态分析 + 真实交互抓包（浏览器内 monkey-patch `fetch`）+ 只读 GET 探针
> 目的：判断"能否从线上站点看出源码"以及"不看源码能否达到同等效果"
> 合规说明：站点是**开放注册的公开 demo**（页面明示"首次输入将自动创建学习账号"）。观察时注册了一个测试账号 `dsh_visitor` 提了 1 个问题、调了 2 个只读接口，**未做任何扫描、爆破、越权或写操作**；该测试账号记录会留存在对方服务器上，如需清理只能由对方管理员处理。

---

## 0. 一句话结论

**"源码"看不到，但"契约"全露了。**

- 前端是**单文件打包的 React SPA，无 sourcemap** → 原始源码文件（.tsx/.vue）无法恢复，只能读压缩后的 bundle。
- 但 bundle 里包含了**接口协议、10 个工具名、模块 key、artifact 结构、证据/分块 schema、系统提示词片段、15 份文档清单、本地兜底语料**。
- 后端（FastAPI + LLM 编排）代码不可见，但 `/api/health` **把全部 10 个工具名列出来了**，配合真实交互能拿到**完整的 SSE 事件协议与数据结构**。
- 结论：**复刻它不需要源码了**——它剩下的唯一"秘密"是切分/检索/门控的具体实现，而这些参数项目书里已经写了（父块/子块、λ=0.35、τ=0.50）。

## 2. 接口协议（完整，可直接照做）

整个系统只有 **3 个真实端点**（第 4 个 `/api/objects` 在 bundle 里出现但线上 404，应为开发残留）：

### 2.1 `POST /api/chat` — 唯一的对话入口

请求体：
```json
{"session_id":"local","messages":[{"role":"user","content":"250 目筛分的作用是什么？"}],"feature":null}
```

响应：**SSE 流**，`data: <json>` 逐帧下发，结尾 `data: [DONE]`。
帧间还夹着**非 SSE 的进度行**：`{"revision":2}`（无 `data:` 前缀），用于前端同步状态版本。

### 2.2 事件类型（一次真实问答的实测统计）

| type | 次数 | 含义 |
|---|---|---|
| `thinking` | 731 | 思考过程，**1–2 字符一帧**（极细粒度） |
| `token` | 673 | 正文流式输出（注意：**不叫 `text`**） |
| `tool_call` | 4 | 工具调用（2 轮 × 2 个工具） |
| `tool_result` | 4 | 工具结果 |
| `artifact` | 4 | 画布数据 |
| `done` | 1 | 结束 |
| `error` | — | bundle 里有 18 处引用，本次未触发 |
| `[DONE]` | 1 | 终止哨兵 |

> **一次问答共 1418 个事件帧、14.3 秒、≤881 tokens**（界面底部实时显示"消息数 · tokens · 耗时"）。

各帧真实样例：
```jsonc
data: {"type": "thinking", "text": "The"}
data: {"type": "tool_call", "id": "call_00_8uGtKptRSFWGkFsNY0m33873",
       "name": "search_knowledge", "label": "检索知识库 ·「250目筛分」",
       "args": {"query": "250目筛分", "top_k": 6}}
data: {"type": "tool_result", "id": "call_00_...", "summary": "命中 1 条 · 劳育模块二 材料制备工艺实践（专业技能劳动模块）",
       "detail": "【1】《2026年劳动教育实践特色项目任务书·教学正文（原文）》… 【原文段落116】…"}
data: {"type": "artifact", "artifactType": "knowledge", "data": {"query":"250目筛分","chunks":[...]}}
data: {"type": "done"}
data: [DONE]
```

**注意 `tool_result.detail` 的结尾固定拼了一句约束**：
> `引用时标注 chunk_id，只依据以上证据作答。`

→ 这就是它"强制 RAG 约束防幻觉"的实现方式：**把约束写在工具返回值的末尾**，而不是只写在系统提示词里。极简且有效。

### 2.3 其它两个端点

| 端点 | 方法 | 用途 | 实测 |
|---|---|---|---|
| `/api/auth/${action}` | GET/POST | 登录/注册/改密/记录 | 同源路径，前端模板串 |
| `/api/auth/records` | PUT | **整份对话历史同步** | body：`{"data":{"mse-agent.history.v1":"<JSON 字符串>"},"revision":N}`，**用 revision 做乐观并发控制** |
| `/api/health` | GET | 健康检查 | 返回模型名 + **全部工具名**（见下） |

## 4. 数据结构（这是最有价值的发现）

### 4.1 chunk / 证据 schema —— 证实"父子双层切分"

```json
{
  "chunkId": "chk_doc_a163fb0e84f8ef3669_0008_0000",
  "documentId": "doc_a163fb0e84f8ef3669",
  "documentTitle": "课程讲义·金相试样制备",
  "category": "课程讲义",
  "section": "7 常用腐蚀剂",
  "score": 0.7513,
  "content": "| 序号 | 腐蚀剂名称 | 成分…",
  "snippet": "| 序号 | 腐蚀剂名称 | 成分…"
}
```

**`chunkId` 的编码规则已被证明**：`chk_<documentId>_<4位父块序号>_<4位子块序号>`
→ `_0008_0000` = 第 8 个父块的第 0 个子块。**这正是项目书说的"章节父块—段落子块"双层切分**，且父块按文档内顺序编号。

→ **对我们的启示**：直接采用同样的编码 `chk_<doc>_<parent>_<child>`，好处是**检索命中子块时，父块 ID 就在字符串里**，无需二次查表即可回溯章节。

### 4.2 artifact schema —— 画布契约

```json
{
  "artifactType": "module2",
  "data": {
    "mode": "search",
    "query": "250目筛分 作用",
    "answer": "",
    "focusedDocIds": [],
    "evidences": [ /* 上面那种 chunk 数组，带 score */ ],
    "documents": [ {"id":"doc_...","title":"课程讲义·金相试样制备","category":"课程讲义",
                    "source":"课程知识库 chunks.jsonl（教材/大纲/讲义/劳育）","status":"ready"} ],
    "totalDocs": 15,
    "baseUrl": "http://127.0.0.1:8765",
    "note": "检索「…」命中 6 段课程原文证据"
  }
}
```

- `artifactType` 取值实测：`knowledge`、`evidence`、`feynman`、`module1`、`module2`、`module4`、**`visual3d`**。
- **画布由 `artifactType` 决定渲染组件**——这就是"前端声明自己认领的可视化数据类型"的落地形态。
- `baseUrl: "http://127.0.0.1:8765"` **泄漏了原 RAG 系统后端地址**（本地 Ollama/服务），说明线上是靠反向代理或同容器 8765 端口访问。

### 4.3 会话与持久化

- `localStorage` 仅 2 个 key：`mse-agent.theme`、`mse-agent.session`。
- 对话历史整份存在 `mse-agent.history.v1`，结构：
  `{conversations:{"conv:<moduleKey>:<hash>":[messages]}, metas:[{id,moduleKey,title,updatedAt}], currentConv:{}, activeConvKey}`
- 消息对象字段：`{id, role, content, streaming, responseMode:"live", thinking, tools:[{id,name,label,args,status,summary,detail}], artifact:{...}}`
- **每次变更都整体 `PUT /api/auth/records` + revision 自增** → 简单粗暴但可靠（无服务端会话状态）。

### 4.4 模块 key（实测）

`__global__`（全局对话）、`module1`、`module2`（知识库RAG）、`module4`（金相组织辨析）、`visual3d`（3D 可视化）。
→ **编号不连续**（缺 module3/5/6），说明模块是"先有后端能力、再挂前端壳"的增量开发，**编号即历史包袱**。这提醒我们：**模块 key 应该用语义名（`tolerance`/`coach`）而不是 `module2`**，否则后期必然错乱。

## 7. 它没做到 / 做得粗糙的地方（我们的机会）

1. **3D 是"分模块散装"的**：`artifactType: visual3d` 只在 3D 模块内用，与对话没有深度耦合；不像策划案要求的"两屏绝对联动"。
2. **画布可整体关闭**（bundle 里有"「知识库RAG」画布当前处于关闭状态，启用后即可查看…"）→ 说明右栏不是稳定布局，是可选面板。策划案要的"三栏恒在"比它更硬。
3. **模块编号 `module1/2/4` 混乱**，缺号。
4. **thinking 是 1–2 字符一帧**，731 帧只为展示一次思考 → 网络事件量浪费（1418 帧/次）。我们可以按 token 批量（20–50 字符/帧）。
5. **历史整份 PUT** + revision → 会话一长就会 O(n) 上行；我们应做增量。
6. **`baseUrl: 127.0.0.1:8765` 泄漏到前端** → 工程卫生问题；我们不要这么干。
7. **无 sourcemap 但有完整文件级结构泄漏** → 反向说明：**真正做到"看不出源码"要靠架构而不是靠压缩**。

## 8. 回答最初的问题

### Q1：能从网站看出源码吗？

**部分能，且足够用。**

| 层级 | 可得性 | 说明 |
|---|---|---|
| 前端原始源码（.tsx） | ❌ | 无 sourcemap，只有压缩 bundle；但可**高保真还原**组件结构、文案、提示词、契约 |
| 前端行为逻辑 | ✅ ~90% | 事件解析、状态管理、artifact 渲染分发规则都在 bundle 里可读 |
| 后端源码 | ❌ | FastAPI 不可见 |
| 后端接口契约 | ✅ 100% | 3 个端点、请求体、SSE 全部实测 |
| 工具清单 | ✅ 100% | `/api/health` 直接返回 |
| 数据结构（chunk/artifact/会话） | ✅ 100% | 交互返回体即完整 schema |
| 语料清单 | ✅ 100% | 15 份文档标题 + 分类 + ID |
| 语料全文 | ✅ 大部分 | 通过检索证据卡可逐段取回 |
| 切分/检索/门控算法 | ❌ | 但**项目书给了全部参数**（父子双层、λ=0.35、τ=0.50） |
| 系统提示词全文 | ⚠️ 片段 | 前端有大量片段，完整版在后端 |

### Q2：不看源码能达到相同效果吗？

**能。而且我们比它当初起步的位置更好。**

理由：

1. **它的门槛不在算法**。整套系统是"FastAPI + 一个 LLM + 一个检索器 + React 三栏壳"，没有任何自研模型或新算法。四个"创新点"里，只有门控有工程巧思（IDF 覆盖率），其余是架构组织。**架构组织是最不怕照抄的。**
2. **我们已有 4 份材料它没有的对照物**：项目书（参数）+ 现在这份站点观察（协议与数据结构）+ 03 的题库底料 + 04 的架构方案。它当年只能从零设计，我们可以直接对齐。
3. **我们还有两个它没有的硬东西**：①题库的"题—图—答"三元组（252 题 CSV）；②需要真几何内核的三视图/剖切（这是差异化而非负担，因为它压根没做）。
4. **它的效果里有相当比例是"内容 + 文案"贡献的**，不是技术。它满共 ~3.5 万字语料 + 51 条本地兜底 QA，就能演示得很完整——说明**"精标小库 + 诚实拒答 + 可视化"已经足够撑起一个作品**，不需要海量数据。

**但要达到"相同效果"，有三件事必须自己做、抄不来：**
- **内容**：机械制图的教材/国标/课件要自己建库（它那 15 份是材料的，一句都用不上）。
- **视觉找茬**：它完全没有；这块只能自己从零做（CV + VLM 两段式）。
- **几何内核**：它的 3D 是参数化球棍；三视图投影/剖切/剖面线必须自己做。

## 9. 对我们的方案要改的 5 处（相对 04 文档）

| # | 原计划 | 依据本次观察 → 修订 |
|---|---|---|
| 1 | 七类事件流（thinking/text/tool_call/tool_result/canvas/error/done） | 改为**六类 + 哨兵**，且正文流式事件名用 `token` 而非 `text`；新增帧间 `{"revision":N}` 进度行。**照它的命名，减少前后端沟通成本** |
| 2 | artifact 用 `kind` 枚举（evidence/comparison/...） | 改为 **`artifactType` 字符串 + `data`**，且 `artifactType` 用**语义名**（`evidence`/`three_view`/`graph`/`tolerance`/`coach`/`feynman`），**不要用 `module2` 这类编号** |
| 3 | chunk_id 自定义 | 采用 **`chk_<docId>_<parent4>_<child4>`**（父块 ID 内嵌，省一次查表） |
| 4 | 门控靠系统提示词 | **双保险**：系统提示词 + **在 `tool_result` 文本末尾追加"只依据以上证据作答，引用标注 chunk_id"**（它的做法，实测有效） |
| 5 | 知识库必须拿到授权才能建 | 国标/制度类可先走**"公开渠道摘编 + 标注来源与核验日期"**（它 5/15 份就是这么来的），把 R1 拆成"能先做的"和"必须等的"两半 |

另外新增一条工程纪律：**不要泄漏内网地址到前端**（它把 `127.0.0.1:8765` 打进了 artifact）。
