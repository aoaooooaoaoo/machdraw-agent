# 13 · 手绘找茬引擎（图形比对与错误分类）

> 对应策划案「智能找茬与错题本」里"视觉批改：学生拍照上传手绘图，AI 圈出漏标尺寸、虚实线混淆等错误"。
> 代码：`apps/api/app/vision/sketch.py`；验收：`apps/api/tests/check_sketch.py`（12/12）

---

## 一、把"AI 判图"拆成可判定的一半

策划案写的是"视觉大模型 + 图像处理算法"。但直接上大模型会得到**不可复核**的评语
（"这里的线好像画错了"），而工程图恰好是**几何**问题——漏没漏一条线、虚线画成实线，
是能算的。

所以拆成两段：

```
学生手绘图 ──① CV/识别──▶ 线段集合 {x1,y1,x2,y2,hidden} ──② 本引擎──▶ 结构化错误列表
                              （几何归一，未来接 CV/VLM）        （可判定，已实现）
```

**本引擎只做第 ② 段**，输入是标准化的线段集合。好处：
- 现在就能用（画板类输入直接可用，不需要先解决手绘识别）；
- 判定结果可复核、可解释、可回归测试；
- 将来接 CV/VLM 只是替换第 ① 段，判定逻辑不变。

## 二、五类错误（全部可判定）

| 类型 | 判据 | 面向学生的说法 |
|---|---|---|
| `missing` 漏画 | 答案里有、学生图上没有 | "这条线漏画了" |
| `extra` 多画 | 学生图上有、答案里没有 | "你的图上多画了一条线" |
| `linetype` 虚实线混淆 | 位置对上了，但 `hidden` 标志相反 | "这条线应该是**虚线**，你画成了**粗实线**" |
| `offset` 位置偏差 | 位置接近但偏离 > 容差（默认 3 mm） | "这条线偏离答案约 6.0 mm（容差 3 mm）" |
| `wrong_angle` 方向错误 | 斜率与答案不一致 | "这条线的方向与答案不一致" |

匹配用**双向端点距离**（学生端点到答案线段的距离 + 答案端点到学生线段的距离，都做截断），
所以"线画短了一点"不会被误判成错误。

角度容差随线长自适应：`da_allowed = angle_tol + atan(2·tol/len)`。
理由很实际——**同一条 1.5 mm 的绝对误差，在 60 mm 长线上是 1.4°，在 6 mm 短线上是 28°**，
不做自适应的话短线段永远判不过。

## 三、三种输出（对应三种教学场景）

| mode | 用途 | 是否下发答案 |
|---|---|---|
| `grade` | 学生提交自己画的线 → 得分 + 错误列表 | 是（要告诉他哪错了） |
| `exercise` | 系统在标准答案里**注入错误** → 让学生找茬 | 否（`answer_withheld: true`） |
| `truth` | 教师/对照界面取标准答案 | 是 |

`inject_errors()` 可注入 `missing / extra / linetype / offset / wrong_angle` 五类，
用于 ① 自测判定能力；② 生成"找茬练习"。

## 四、验收（12/12 通过）

| 用例 | 期望 | 实得 |
|---|---|---|
| 完全正确的图 | 得分 1.0、零错误、通过 | ✅ |
| 注入 `missing` | 检出「漏画」 | ✅ |
| 注入 `linetype` | 检出「虚实线混淆」 | ✅ |
| 注入 `offset` | 检出「位置偏差」 | ✅ |
| 注入 `extra` | 检出「多画」 | ✅ |
| 同时注入 3 类 | 3 类都检出 | ✅ `{offset 1, linetype 1, missing 1}` |
| 空图 | 全部判漏画、未通过 | ✅ 20/20 |
| 只画主视图 | 得分 0.30、未通过 | ✅ 6/20 |
| 每条线偏 1.5 mm 的"手绘" | 判通过（容差生效） | ✅ 得分 1.0 |

## 五、接口

| 接口 / 工具 | 说明 |
|---|---|
| `GET /api/sketch/truth?model_id=&view=` | 取标准答案线段 |
| `GET /api/sketch/exercise?model_id=&view=&inject=` | 生成找茬练习（答案不下发） |
| `POST /api/sketch/grade` | 提交线段集合 → 结构化错误 |
| 工具 `sketch_grade` | 对话里说"帮我找茬/批改/我画的"即触发，产物 `artifactType="annotation"` |

## 六、诚实边界（写进 `note` 字段，不藏着）

> 只做几何级判定：漏画/多画/虚实线/位置/方向。
> 尺寸数值、剖面线间距、粗糙度符号、国标细节等需教师复核。

这正是策划案里"AI 找茬"应有的姿态：**能判的说准，判不了的说明判不了**。

## 七、下一步

1. **接第 ① 段**：手绘照片 → 线段集合。可先用 OpenCV（Hough 直线/圆弧检测 + 线宽分级），
   再让 VLM 复核语义（这块是否该有剖面线）。有了真实学生作业样本才能定阈值。
2. **尺寸标注判定**：需要 OCR 抓数字与符号（Φ/R/□/C），再与答案的标注集合比对。
3. **剖面线判定**：剖面线是"一组等间距 45° 平行线"，可以用方向-间距直方图判存在性与方向正确性。
4. **前端画板**：目前没有绘图输入，学生只能提交程序生成的线段。
   前端加一块"在图上画线"的画板，这块能力才真正可交互。
