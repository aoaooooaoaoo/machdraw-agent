## 1. 分层架构与一次完整请求的调用链

### 1.1 五层结构（真实分层，不是概念图）

| 层 | 目录/文件 | 职责 | 对核反应堆物理的复用度 |
|---|---|---|---|
| L1 入口层 | `apps/api/app/main.py`（704 行） | FastAPI 装配、27 个 HTTP 路由、CORS、静态资源、SSE `StreamingResponse` | **照搬**（改品牌串与路由裁剪） |

| L3 能力层 | `tools/`（11 个工具 + `spec.py` + `base.py` + 自注册 `__init__.py`）、`modules/`（feynman / wrongbook） | 单位能力；确定性引擎全部下沉到 `domain/`、`geometry/`、`vision/` | 工具总线**照搬**，11 个工具**重写** |
| L4 检索层 | `rag/`（symbols / tokenize / chunking / index / retrieve 共 783 行） | 符号归一 → 分词 → 切分 → 索引 → 混合检索 → 双门控 | **基本照搬**（约 90%），只换符号表与领域词典 |

数据流一句话：**`main.py` 启动装载一次（state）→ `POST /api/chat` 交给 `orchestrator.run_chat` 异步生成器 → 每个工具产出 `ToolOutcome` → 编排器把工具结果翻译成 7 类 SSE 事件 → 前端 `store.applyEvent` 把 `artifact` 帧挂到画布 → 注册表按 `artifactType` 选渲染器。**

## 2. 契约

### 2.1 SSE 七类事件逐字段（`contracts/models.py:79-105`、`events.py:14-68`）

`EventType` 枚举实测 7 个值：`thinking / token / tool_call / tool_result / artifact / error / done`；流尾另有协议级 `data: [DONE]`（不是 JSON 帧）。README 说的"六类"= 六类业务事件（不含 error）。

一帧的公共壳（Pydantic `SSEEvent`，字段全部有默认值）：

| 字段 | 类型 | 出现在 | 含义 |
|---|---|---|---|
| `type` | `EventType` | 全部 | 事件类型（**唯一必填**） |
| `seq` | int=0 | 全部 | 事件序号；由 orchestrator 自增。**注意 `token` 帧不传 seq，恒为 0**（`events.py:18-19` 默认参数） |
| `text` | str | thinking / token / error | 文本；error 时是错误信息 |
| `id` | str | tool_call / tool_result | 调用 id，格式 `call_<uuid10>`（`orchestrator.py:397`） |
| `name` | str | tool_call / tool_result | 工具名（等于 `ToolSpec.name`） |
| `label` | str | tool_call | 展示文案，含参数占位符展开，如 `检索课程原文 · 「剖视图」`（`orchestrator.py:100-110`） |
| `args` | dict | tool_call | 工具入参 |
| `summary` | str | tool_result | 一句话结果（前端工具卡标题下显示） |
| `detail` | str | tool_result | 多行明细（前端折叠展开显示） |
| `artifactType` | str | artifact | 9 类之一 |
| `data` | dict | artifact / done | artifact 数据体；done 里是 `{provider,model,evidence,coverage,ms}` |
| `code` | str | error | 机器可读错误码（`EMPTY_QUERY` / `INTERNAL`） |

序列化细节（**前端解析必须知道**，`events.py:54-62`）：
- `model_dump(exclude_none=True)`；
- 再对 `text/id/name/label/args/summary/detail/artifactType/data/code` 做"空值剔除"：`"" / {} / [] / 0` 都会从 payload 移除；
- 所以**空 `args` 的 tool_call 帧里没有 `args` 字段**，前端必须 `ev.args || {}`；
- `seq=0` 不会被剔除（不在剔除名单里），因此 token 帧带 `"seq":0`。

逐类事件构造器与典型 payload：

```python
# thinking（orchestrator.py:323）
{"type":"thinking","seq":1,"text":"学生提问：…。当前模块：…。先判断需要哪些工具…"}
# token（每 24 字一帧，orchestrator.py:438 / events.py:74-76）
{"type":"token","seq":0,"text":"**结论**：三视图的投影规律是…"}
# tool_call
{"type":"tool_call","seq":3,"id":"call_9f3a2b1c07","name":"kb_search",
 "label":"检索课程原文 · 「三视图投影规律」","args":{"query":"三视图投影规律","top_k":6}}
# tool_result
{"type":"tool_result","seq":4,"id":"call_9f3a2b1c07","name":"kb_search",
 "summary":"命中 6 段原文证据 · 「三视图投影规律」· 配图 2 张","detail":"检索到 6 段（top_k=6）：\n…引用时标注 chunk_id，只依据以上证据作答。"}
# artifact
{"type":"artifact","seq":5,"artifactType":"evidence","data":{…见 2.2…}}
# error
{"type":"error","code":"INTERNAL","text":"RuntimeError: …"}
# done
{"type":"done","seq":12,"data":{"provider":"deterministic","model":"tolerance_calc",
 "evidence":0,"coverage":0.0,"ms":31}}
```

`EVIDENCE_CONSTRAINT = "引用时标注 chunk_id，只依据以上证据作答。"`（`tools/base.py:14`）——固定拼在 `kb_search` 的 detail 尾部，属于**提示词级**耦合，可原样保留。

### 2.2 Artifact 与 9 类画布（旧工程实测；SPEC 现行为 8 类）的完整数据结构

`ARTIFACT_TYPES`（`models.py:110-120`）：`evidence / comparison / annotation / three_view / graph / tolerance / coach / quiz / wrongbook`。`Artifact` 只有两个字段：`{artifactType: str, data: dict}`（`models.py:123-125`）。

> **旧工程 9 类，SPEC 现行 8 类**：`evidence / calc / plot / comparison / annotation / quiz / wrongbook / graph`——即 `tolerance→calc`、`three_view→plot`，**并删掉 `coach`**（分步作图动画在核物理课程无对应交付物，其"分步"能力由 `calc` 的 `formulas` 步与 `annotation` 的"计算步骤标注"承担）。所以：`apps/web/src/features/coach/` + `apps/web/src/modules/coach/` **不进入新工程**（见 00c §11.4、§13-E）。下表按旧工程逐类给出 data 字段（改造时"换皮不换骨"）。
