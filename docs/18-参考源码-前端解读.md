## 1. 模块契约：`FeatureModule` / `FeatureProps`

> 这是整个参考作品最值得抄的一节。**先抄协议，再抄模块。**

### 1.1 `ArtifactType` 故意是开放字符串

`src/lib/types.ts:45-66`：

```ts
/* ─────────────── Artifact 协议 ─────────────── */

/**
 * ★ 开放的字符串类型，**故意不做成联合类型**。
 *
 * 原因：模块会换。如果这里写死 6 个名字，那每换一个模块都得改这个公共文件，
 * 而它是 🟡「先问再改」级别 —— 等于每次换模块都要全员协调一次，太笨重。
 *
 * 现在模块是**自注册**的：新建 `features/<名>/index.ts` 并声明 `artifactTypes`，
 * 就自动生效，**不用改任何公共文件**。
 *
 * 代价：拼写错误编译期查不出来。用两道运行时保障兜住：
 *   1. `registry.ts` 发现重名会 warn
 *   2. `ArtifactPanel` 收到没人认领的类型会显示「未实现」而不是白屏
 *   3. `scripts/check-boundaries.py` 静态检查重名
 */
export type ArtifactType = string

export interface Artifact {
  artifactType: ArtifactType
  data: unknown
}
```

> **对我们的启示**：我们现在的 `registry.ts` 是「中心化映射表」；参考作品是「开放类型 + 自注册 + 运行时兜底」。
> 模块一多，中心化表每加一个模块都要改公共文件，是协作瓶颈。可以把 `artifactType` 保持 `string`，
> 用运行时 warn + 未知类型占位兜底（我们已经做了后者）。

### 1.2 `FeatureProps`：模块能拿到的全部能力（只有 5 个）

`src/lib/types.ts:68-86`：

```ts
export interface FeatureProps {
  /** 当前产物。null 表示用户刚切到该功能、还没有数据 */
  artifact: Artifact | null
  /** 功能组件想发消息给 Agent 时调用 */
  onSendMessage: (text: string) => void
  /** 功能组件想把新产物推给画布时调用 */
  onEmitArtifact: (type: ArtifactType, data: unknown) => void
  /**
   * 当前对话的消息（只读）。
   *
   * ★ 整页模式**必须**用它 —— 整页下壳不渲染对话栏，如果模块自己不画出来，
   *   用户就看不到 Agent 的回答、看不到工具调用卡片，等于「Agent 消失了」。
   *   这是硬规矩 3（必须留一个能看见 Agent 干活的入口）的实现手段。
   *   画布模式的模块一般用不到。
   */
  messages?: Message[]
  /** Agent 是否正在生成。整页模式用它显示「正在思考…」之类 */
  busy?: boolean
}
```

关键设计：

- **模块不能自己发网络请求**。要数据 → `onSendMessage('请调用 tools 的 ...')`，让 Agent 去调后端工具。
- **模块可以自己造 artifact**（如错题集手动录入）→ `onEmitArtifact(type, data)`，壳直接更新右栏。
- **整页模式没有对话栏**，所以给 `messages/busy`，模块要自己画一个「能看见 Agent 干活」的区域
  （module1 的 `AgentPanel.tsx` 是标准答案，见 §4.6）。

> **对我们的启示**：可以直接搬。我们的模块目前通过全局 store 拿数据、`send()` 发消息；
> 改成 props 注入更利于「一个模块单独跑起来」。`onEmitArtifact` 这个口子我们还没有，
> 它让模块的本地交互（录入、筛选、练习）也能反向更新画布。

### 1.3 `FeatureModule` 全文：一个模块要交的「五件套 + 三个可选开关」

`src/lib/types.ts:88-167`（注释保留，代码原样）：

```ts
/**
 * 每个 features/<name>/index.ts 必须默认导出这个结构。
 * id 必须与文件夹名一致；artifactTypes 全局唯一。
 */
export interface FeatureModule {
  id: string
  title: string
  /** Optional deterministic source lookup before model/mock routing. Null preserves the existing route. */
  answerFromSources?: (query: string, offline: boolean) => { content: string; summary: string } | null

  /**
   * ★ 给 Agent 的模块身份说明（可选）—— 模块作者写「这个模块在教学上负责什么」。
   *
   * 它随每次请求发给后端，被拼进系统提示词。有它，Agent 在「费曼追问」模块里
   * 就知道自己当前位于该模块、负责什么，而不会只笼统回答「我是教学智能体」。
   * 不填也能用：Agent 仍会知道自己「正在【title】模块中对话」，只是说不出职责。
   *
   * ⚠️ 只写**职责 / 范围**，不要写「你有什么能力、什么权限」——
   *    知识边界、溯源要求、必须调工具这些由 backend/app/config.py 的 SYSTEM_PROMPT 授予，
   *    写在这里既不生效、还会和它打架。
   *
   * ⚠️ 技术约束：单行、≤100 字；不要出现 `id:` / `title:` / `order:` / `artifactTypes:`
   *    这些字样（scripts/ 下的脚本用正则扫 index.ts，取最左匹配，会被文案污染）；
   *    不要用英文撇号（脚手架模板用单引号字符串，会把字符串截断）。
   */
  persona?: string

  artifactTypes: ArtifactType[]
  /** 左栏排序，小的在前 */
  order: number
  /**
   * ★ 开发预览用的样例数据。
   *
   * 在左栏点这个功能时，如果没有真实产物，壳就用这份数据渲染你的组件。
   * 这样每个人**不需要后端、不需要 API Key、不需要走 Agent 流程**，
   * 就能单独看到自己做出来的效果 —— 这是并行开发的前提。
   *
   * 放在 features/<你的功能>/preview.ts 里，壳会在画布上标注「预览数据」以示区分。
   * 不填则点进去是空状态。
   */
  preview?: unknown

  /**
   * ★ 产出 artifact 时，要不要**自动展开**右侧画布（可选，默认 false）。
   *
   * 判据只有一条：**这个模块的交付物是不是那块画布本身？**
   *
   * - **展示型模块 → true**：3D 晶体、图谱、图表、动画。这些东西用文字根本表达不了，
   *   画布弹出等于「你要看的东西来了」，是加分项。
   * - **对话型模块 → false**：追问、讲解、批改这类，内容全在对话流里，
   *   画布只是个附带记录。自动弹出等于从问答区抢走一块屏幕，纯干扰。
   *   （费曼追问就是典型：追问/回答/点评都在对话里，时间线画布属于冗余。
   *   学生想看，点顶栏的画布按钮即可 —— 点左栏模块是**不会**展开它的。）
   *
   * 不填 = false。**保守是刻意的** —— 一个模块擅自抢屏，比少弹一次烦人得多。
   */
  autoOpenCanvas?: boolean

  /**
   * 画布模式组件（默认）。渲染在右栏画布里，和对话流并排。
   */
  Component: ComponentType<FeatureProps>

  /**
   * ★ 整页模式组件（可选）。
   *
   * 填了它，点这个模块时**主区整个换成这个组件** —— 壳的顶栏、对话流、输入框全部让位。
   * 壳只保留左栏导航。模块依旧拿得到 onSendMessage，所以照样能驱动 Agent。
   *
   * ⚠️ **只在「确实需要另一种交互形态」时用**（管理型界面、多 tab 工作台、上传/索引/浏览…）。
   *    展示型的模块（3D、图谱、图表、动画）用 Component + 画布全屏就够了，**别开整页**。
   *
   * 四条硬规矩（详见根目录 AGENTS.md）：
   *   1. 左栏永远是壳的，模块不许改
   *   2. 配色/字体/圆角必须用 tokens.css 的变量，不许自造一套设计语言
   *   3. 必须留一个「返回对话」的出口
   *   4. 克制 —— 8 个模块里最多 2~3 个用整页
   */
  page?: ComponentType<FeatureProps>
}
```

### 1.5 自注册：`import.meta.glob` 扫 `features/*/index.ts`

`src/lib/registry.ts:10-58`（全文关键段）：

```ts
import type { ArtifactType, FeatureModule } from './types'

const modules = import.meta.glob<{ default: FeatureModule }>('../features/*/index.ts', {
  eager: true,
})

export const features: FeatureModule[] = Object.values(modules)
  .map((m) => m.default)
  .filter(Boolean)
  .sort((a, b) => a.order - b.order)

/** artifactType → 负责渲染它的功能组件 */
const byArtifact = new Map<ArtifactType, FeatureModule>()
for (const f of features) {
  for (const t of f.artifactTypes) {
    if (byArtifact.has(t)) {
      console.warn(
        `[registry] artifactType "${t}" 被 "${byArtifact.get(t)!.id}" 和 "${f.id}" 同时注册。` +
          `每个类型只能有一个 owner，见 README.md 的「三、契约」`,
      )
    }
    byArtifact.set(t, f)
  }
}

export function featureByArtifact(type: ArtifactType): FeatureModule | undefined {
  return byArtifact.get(type)
}

export function knownArtifactTypes(): string[] {
  return [...byArtifact.keys()].sort()
}

export function isRegisteredArtifact(type: string): boolean {
  return byArtifact.has(type)
}

export function featureById(id: string): FeatureModule | undefined {
  return features.find((f) => f.id === id)
}

// 开发期自检：把注册结果打到控制台，方便确认自己的功能挂上了
if (import.meta.env.DEV) {
  console.info(
    '[registry] 已注册功能:',
    features.map((f) => `${f.id}(${f.artifactTypes.join(',') || '无画布'})`).join('  '),
  )
}
```

机制拆解：

| 问题 | 答案 |
|---|---|
| 怎么发现模块？ | Vite 编译期把 `../features/*/index.ts` 展开成**静态 import**（`eager:true`），不是运行时读目录 |
| 注册顺序？ | `order` 升序；左栏按这个顺序渲染。module1=10、module2=20、mistakeBook=30、module4=40、visual3d=70、feynman=80 |
| 重名怎么办？ | 只 `console.warn`，**后注册的覆盖先注册的**（`byArtifact.set` 无条件覆盖，Map 保留后者）——所以「重名」最终是**后写赢**，warn 只是提醒，不是阻断 |
| 一个模块能认领多个类型吗？ | 能。`artifactTypes: ['a','b']` 都会指向同一个 owner；但一个类型只能有一个 owner |
| 没人认领的 artifact 怎么显示？ | 两条路：① SSE 到达时 `App.tsx:398-404` 直接 `return`，**不进画布**；② 历史恢复出一个没人认领的类型时，`ArtifactPanel.tsx:73-83` 显示明确报错（见 §3.2） |
| 新增模块要改哪些公共文件？ | **零个**。新建 `features/<name>/index.ts` + `preview`，`import.meta.glob` 自动捡到 |
| 类型拼错会怎样？ | 编译期不报（`ArtifactType=string`）；运行时：重名 warn / 未知类型占位 / `scripts/check-boundaries.py` 静态查重 |

### 2.1 三栏是 CSS Grid，不是三个 flex 容器

```css
/* ── 三栏骨架 ── */

  display: grid;
  grid-template-columns: var(--sidebar-w) minmax(0, 1fr) var(--artifact-w);
  /* ★ 必须显式声明行高。
```

### 2.4 artifact 怎么被分配到右栏（完整链路）

3. **同步到画布**：切换会话时，从最新消息倒着找最后一个 artifact：

   `src/lib/history.ts:17-23`：

### 2.7 多会话：会话 id 里编码模块，纯函数推导

`src/lib/history.ts:5-9, 25-27, 47-74`：

```ts
/**
 * 数据模型：每个模块（含全局对话空间）可以有任意多条对话。
 *   - 已落库的对话 id：`conv:<moduleKey>:<rand>`，moduleKey 编码在 id 里，
 *     所以从任何一条 id 都能纯函数推出它属于哪个模块，不用查表。
 *   - 还没说过话的草稿：`draft:<moduleKey>`。不写库、不占列表 ——
 *     点「新对话」只切到一个空草稿，发出第一条消息时才 materialize 成 conv id。
 */
export const GLOBAL_CONV = '__global__'

export const isDraftId = (key: string) => key.startsWith('draft:')
export const draftId = (moduleKey: string) => `draft:${moduleKey}`
export const newConvId = (moduleKey: string) =>
  `conv:${moduleKey}:${crypto.randomUUID().replace(/-/g, '').slice(0, 10)}`

/** conv/draft id → 所属模块 key */
export const moduleKeyOf = (key: string) => key.split(':')[1] || GLOBAL_CONV

/** 打开某模块时进哪条对话：上次打开的 → 最新一条历史 → 空草稿 */
export function resolveConvKey(moduleKey, metas, currentConv) {
  const cur = currentConv[moduleKey]
  if (cur && (isDraftId(cur) || metas.some((m) => m.id === cur))) return cur
  const latest = metas.filter((m) => m.moduleKey === moduleKey).sort((a, b) => b.updatedAt - a.updatedAt)[0]
  return latest?.id ?? draftId(moduleKey)
}
```

落库防抖 400ms（`App.tsx:205-214`）；`pagehide` 也 flush；
`loadStore`（`history.ts:80-134`）会做迁移（`knowledgeBase→module2`）、清理无效会话、把 `streaming` 全部置 false。
quota 爆掉时剥掉图片 data URL 再存一次（`history.ts:136-159`）。

> **对我们的启示**：我们的 per-feature session 只在内存里；参考作品的「会话 id 编码模块 + 草稿延迟落库」
> 是很好的补课方向。尤其「退出时把 streaming 清掉」这个细节，我们刷新页面会永远转圈。

#### 4.3.1 向量工具与旋转矩阵（`galaxyLayout.ts:12-45`）

```ts
export type Vec3 = [number, number, number]

const add = (a: Vec3, b: Vec3): Vec3 => [a[0] + b[0], a[1] + b[1], a[2] + b[2]]
const sub = (a: Vec3, b: Vec3): Vec3 => [a[0] - b[0], a[1] - b[1], a[2] - b[2]]
const scale = (a: Vec3, s: number): Vec3 => [a[0] * s, a[1] * s, a[2] * s]
const norm = (a: Vec3): Vec3 => {
  const l = Math.hypot(a[0], a[1], a[2]) || 1
  return [a[0] / l, a[1] / l, a[2] / l]
}
const cross = (a: Vec3, b: Vec3): Vec3 => [
  a[1] * b[2] - a[2] * b[1],
  a[2] * b[0] - a[0] * b[2],
  a[0] * b[1] - a[1] * b[0],
]

function rot(v: Vec3, t: readonly number[]): Vec3 {
  let [x, y, z] = v
  const [rx, ry, rz] = t
  let c = Math.cos(rx)
  let s = Math.sin(rx)
  ;[y, z] = [y * c - z * s, y * s + z * c]          // 绕 X
  c = Math.cos(ry)
  s = Math.sin(ry)
  ;[x, z] = [x * c + z * s, -x * s + z * c]         // 绕 Y
  c = Math.cos(rz)
  s = Math.sin(rz)
  ;[x, y] = [x * c - y * s, x * s + y * c]          // 绕 Z
  return [x, y, z]
}

/** 星系轨道面的正交基：u / w 为盘面两轴，n 为法向 */
export function tiltBasis(tilt: readonly number[]): [Vec3, Vec3, Vec3] {
  return [rot([1, 0, 0], tilt), rot([0, 0, 1], tilt), rot([0, 1, 0], tilt)]
}
```

即：把标准基 `x`、`z`、`y` 分别按该星系的 `tilt=[rx,ry,rz]` 旋转，得到盘面两轴 `u,w` 和法向 `n`。

#### 4.3.2 稳定散列：同一节点每次布局一致（`galaxyLayout.ts:47-55`）

```ts
/** 稳定的字符串散列，保证每次渲染布局一致 */
function seedOf(s: string): number {
  let h = 2166136261
  for (let i = 0; i < s.length; i += 1) {
    h ^= s.charCodeAt(i)
    h = Math.imul(h, 16777619)
  }
  return ((h >>> 0) % 1000) / 1000       // [0,1)
}
```

FNV-1a → 映射到 [0,1)，用于给扇区起始角加随机但稳定的偏移。

```ts
    const cid = l2.get(i)
    if (!cid) return

    const [u, w, nrm] = tiltBasis(sec.tilt)
    const kids = childrenOf(cid).filter((k) => k.level === 3)
    const r = 6.4
    kids.forEach((k, j) => {
      const a = (j / Math.max(1, kids.length)) * Math.PI * 2 + i * 0.62
      const ring = add(scale(u, Math.cos(a) * r), scale(w, Math.sin(a) * r))
      pos.set(k.id, add(add(c, ring), scale(nrm, ((j % 3) - 1) * 0.85)))
    })
  })

  // 四/五级：绕父节点、沿「星系中心 → 父节点」向外扇形展开

    for (const par of KNOWLEDGE_NODES.filter((n) => n.level === level - 1)) {
      const p = pos.get(par.id)
      if (!p) continue
      const cc = pos.get(l2.get(par.sector) ?? 'root') ?? ([0, 0, 0] as Vec3)
      const d = norm(sub(p, cc))                       // 从星系中心指向父节点的方向
      const helper: Vec3 = Math.abs(d[1]) < 0.9 ? [0, 1, 0] : [1, 0, 0]
      const u = norm(cross(d, helper))
      const w = cross(d, u)
      const kids = childrenOf(par.id).filter((k) => k.level === level)
      kids.forEach((k, j) => {
        const a = (j / Math.max(1, kids.length)) * Math.PI * 2 + seedOf(par.id) * 6.28
        const fan = add(scale(u, Math.cos(a) * radius), scale(w, Math.sin(a) * radius))
        pos.set(k.id, add(add(p, scale(d, out + (j % 2) * 0.8)), fan))
      })
    }
  }
  placeSub(4, 3.0, 1.2)
  placeSub(5, 2.2, 0.9)
```

公式整理（照这个实现即可）：

- 三级（专题）在星系盘面成环：
  `a_j = j/n · 2π + i·0.62`
  `P = C + u·(r·cos a_j) + w·(r·sin a_j) + n·(((j mod 3) − 1)·0.85)`，`r = 6.4`
- 四级/五级（子节点）沿「星系中心 → 父节点」方向扇形展开：
  `d = normalize(P_parent − C_sector)`
  `u = normalize(d × helper)`，`w = d × u`（`helper` 取与 `d` 不平行的轴）
  `a_j = j/n · 2π + seed(parent)·2π`
  `P = P_parent + d·(out + (j mod 2)·0.8) + u·(radius·cos a_j) + w·(radius·sin a_j)`
  `placeSub(4, 3.0, 1.2)`、`placeSub(5, 2.2, 0.9)`

#### 4.3.4 斥力松弛：保证星点不遮挡（`galaxyLayout.ts:115-137`）

```ts
// 全局斥力松弛：团内 >= 1.9、跨星团 >= 2.6（单位远大于星球半径，保证不遮挡）
const lv = (id: string) => nodeById(id)?.level ?? 1
const sc = (id: string) => nodeById(id)?.sector ?? -1
const ids = [...pos.keys()].filter((id) => lv(id) >= 3)
for (let it = 0; it < 20; it += 1) {
  for (let i = 0; i < ids.length; i += 1) {
    for (let j = i + 1; j < ids.length; j += 1) {
      const a = pos.get(ids[i])!
      const b = pos.get(ids[j])!
      const dx = b[0] - a[0]
      const dy = b[1] - a[1]
      const dz = b[2] - a[2]
      const dist = Math.hypot(dx, dy, dz) || 0.01
      const minD = sc(ids[i]) === sc(ids[j]) ? 1.9 : 2.6
      if (dist < minD) {
        const push = ((minD - dist) / dist) * 0.35
        pos.set(ids[i], [a[0] - dx * push, a[1] - dy * push, a[2] - dz * push])
        pos.set(ids[j], [b[0] + dx * push, b[1] + dy * push, b[2] + dz * push])
      }
    }
  }
}
```

O(n²×20) 对 70 个节点完全够用；`0.35` 是阻尼，迭代 20 次收敛。
兜底：任何漏放节点锚到父节点附近（`galaxyLayout.ts:106-113`）。

> **对我们的启示**：**可直接搬公式**（2D 也适用：把 y/z 压成平面即可）。
> 我们的全览星图目前是「手工 9 星系 + 螺旋」，可升级为「先定星系中心 → 环/扇形初排 → 斥力松弛」，

#### 4.4.2 相机飞行：`CameraRig`（`KnowledgeGraph.tsx:123-179`）

```tsx
function CameraRig({ fly, viewRef, onDist }) {
  const controls = useThree((s) => s.controls)
  const camera = useThree((s) => s.camera)
  const goal = useRef(null)

  useEffect(() => {
    if (!fly) return
    goal.current = {
      t: new THREE.Vector3(...fly.t),
      d: fly.d,
      dir: fly.dir ? new THREE.Vector3(...fly.dir).normalize() : null,
    }
  }, [fly])

  // 用户一旦拖拽（controls 'start'）立刻取消飞行，避免和 OrbitControls 打架
  useEffect(() => {
    if (!controls) return
    const stop = () => { goal.current = null }
    controls.addEventListener('start', stop)
    return () => controls.removeEventListener('start', stop)
  }, [controls])

  useFrame((_, delta) => {
    if (!controls) return
    const g = goal.current
    if (g) {
      const k = 1 - Math.exp(-delta * 4.2)          // 帧率无关的阻尼
      controls.target.lerp(g.t, k)
      const cur = camera.position.clone().sub(controls.target)
      const dir = cur.lengthSq() > 1e-6 ? cur.normalize() : new THREE.Vector3(0, 0.3, 1)
      if (g.dir) dir.lerp(g.dir, k).normalize()
      const len = camera.position.distanceTo(controls.target)
      const nl = THREE.MathUtils.lerp(len, g.d, k)
      camera.position.copy(controls.target).addScaledVector(dir, nl)
      controls.update()
      if (controls.target.distanceTo(g.t) < 0.02 && Math.abs(nl - g.d) < 0.05) goal.current = null
    }
    const d = camera.position.distanceTo(controls.target)
    viewRef.current = { t: [controls.target.x, controls.target.y, controls.target.z], d }
    if (Math.abs(d - lastD.current) > 1.5) { lastD.current = d; onDist(d) }
  })
  return null
}
```

要点：

- `viewRef` 把当前 target/distance 暴露给外部（缩放按钮、提示文案用）。

### 4.8 照着实现的最小步骤（不看原码也能落地）

1. **建数据表**：`KnowledgeNode{id,label,level(1-5),sector(0-5),parent,kind?,desc,refs}`、
   `KnowledgeEdge{source,target,relation(前置依赖/因果/对比/组成)}`、
   `QuestionNode{id,tier(1-3),title,bloom,knowledgeIds,answer[],blindSpot?,refs}`、
   `QuestionEdge{source,target,relation}`。树边由 `parent` 自动生成（组成），其余手工补。
2. **定星系**：`SECTORS` 六个中心（3D 坐标 + tilt）或 2D 版九个角度；写 `LEVEL_STYLE` 颜色/半径。
3. **算布局**：三级 `a_j=j/n·2π+i·0.62` 在盘面成环；四/五级沿 `d=normalize(P_parent−C_sector)` 扇形；
   最后 20 次 O(n²) 斥力松弛（同团 1.9、跨团 2.6，阻尼 0.35）。
4. **画场景**：中心根节点 + 节点（发光球/光晕）+ 边（组成直线、跨团二次贝塞尔，中点外推 `min(7,|AB|·0.22)`）。
5. **加交互**：点击节点 → 相机/视图飞越（`k=1−e^(−delta·4.2)` 阻尼，距离按 `FLY_DIST[level]`）；
   选中后 `highlightSet = 自己+父+子+跨团关联`，其余 dim；再点一次回全景；空白点击取消；面包屑回跳。
6. **加筛选**：`hiddenLevels`/`hiddenSectors` 两个 Set；搜索取前 7 个匹配并飞越；
   预设视角 = 改 `{t,d,dir}`；缩放按钮 = 改 `fly.d`。
7. **画问题图**：三列 CSS Grid；`ResizeObserver` + `getBoundingClientRect` 量每个卡片左右锚点；
   按 source 分组，同源按目标 y 排序后以 10px 扇形散开，`C` 控制点 `dx=max(48,Δx·0.46)`；
   `questionPath` DFS 求上下游，路径内边高亮 + 流动虚线，其余 dim。
8. **串双视图**：`graphNav{tab,kFocus,qFocus,jumpToKnowledge,jumpToQuestion}`；
   artifact 只带 `{mode,focus}`；两边 `focusId` 的 effect 各自解禁过滤 + 定位；整页模式加 Agent 抽屉。

画布合并顺序：artifact 条目在前 + 本地记录按 id 去重在后（`Component.tsx` 的 `merged`）。

**禁用开关**（`enable.ts` + `index.ts:30-32`）：localStorage 键 `plugin.mistakeBook.enabled`；
禁用只影响画布内容（显示「插件已禁用」卡片），**左栏入口常驻**，可一键启用。

### 7.2 feynman：逐句标注 + 三轮门槛

**数据契约**（`feynman/AGENTS.md:36-54`，实现见 `Component.tsx:14-32`）：

```ts
interface Round {
  question: string
  userAnswer: string
  critique: string
  annotated?: Segment[]   // 后端 _annotate 切好的互不重叠完整分段
}
interface Segment { text: string; kind?: 'vague' | 'jump' | 'good' | null; note?: string }
interface Payload {
  concept?: string
  rounds?: Round[]
  score?: number | null
  overall?: string
  suggestions?: string[]
}
```

**硬不变式**：各段 `text` 顺次拼接必须与 `userAnswer` **逐字相同**；
切分在后端做，前端只渲染（`AGENTS.md:59-65`）。模型只给 `quote`，后端子串匹配定位，
**对不上原文的引文直接丢弃**（宁可少标，不可标错位置）。

**交互**（`Component.tsx:61-112`）：

- 标注段用 `<button>` 内联在正文里，三种颜色只改**底色 + 下划线**，不改文字颜色；
- **点击**显示该句点评（刻意不用 hover 浮层——录屏时鼠标 hover 录不进去，`55-60`）；
- 没标注/引文全丢时回落纯文本（`69-73`），不白屏。

**三轮门槛**（`Component.tsx:114-131`）：

```ts
const rounds = Array.isArray(data?.rounds) ? data.rounds : []
// ★ 「已回答」的轮次才算有效轮次。后端在 Agent 刚抛出问题、学生还没开口时也会记一轮，
//   那种 userAnswer 为空的轮次不能算进三轮门槛。
const answered = rounds.filter((round) => round.userAnswer).length
// 分数只可能在后端判定满三轮后才下发，所以「有没有分」就是完成与否的权威信号
const complete = typeof data?.score === 'number'
```

**空态**：`concepts.ts` 提供 10 个「课程概念起点」（过冷度、形核、金相制样、相与组织、维氏硬度、
热膨胀、回火、铁碳相图、FCC/HCP 堆垛、BCC 密排面），点一下就把「用费曼技巧学习 X」发进对话。

> **对我们的启示**：
> ① 错题集六段式可以直接映射到我们的「智能线茬与错题本」——我们已有六步，但缺少「学生错误答案/根因类型/避坑」三段；
> ② 本地 localStorage + `window.__xxxDebug` 自检 API 很适合答辩前自测；
> ③ 费曼的「逐句标注 + 点击看点评」可以搬去我们的「费曼追问」模块；
> ④ 「已回答轮次」而不是 `rounds.length` 这个坑，任何有「Agent 先出题、学生后答」的流程都要注意。

## 附录 B · 和我们机械制图现有实现的最大差异

| 维度 | 参考作品 | 我们（`apps/web`） | 建议 |
|---|---|---|---|
| 模块注册 | Vite `import.meta.glob` **自注册**，`FeatureModule` 默认导出 | 中心化 `modules/registry.ts` 手工映射 | 抄自注册，壳只查表 |
| 模块契约 | `FeatureProps` 注入（artifact/send/emit/messages/busy） | Zustand store 全局取用 | 至少把 `onEmitArtifact` 补上 |
| 图谱数据 | 前端静态 `graphData.ts`（71/105） | 后端 `/api/graph`（169/279 + 问题分层） | 布局/交互在前端，知识数据在后端 |
| 3D | R3F + three（真 WebGL） | 明确不用 three.js，SVG 2D/2.5D | 不引库；用投影/渐变/辉光仿 3D |
| 样式 | tokens.css + 每模块内联 `<style>`/module.css | 单一 `app.css` | 保持单一，模块只加前缀 class |
| 会话 | 多会话 localStorage（`conv:<module>:<rand>`） | 内存 per-feature session | 补持久化与草稿 |
| 模式 | 画布 + 可选整页（`page`） | 只有右栏画布 | 若图谱/辨析要更大舞台，加 `page` |
| 认证 | Bearer token + `/api/auth/*` | `X-Account` 自动注册 | 不迁移，保持后端契约 |

**最大的架构差异一句话**：
参考作品是「**壳只认协议、模块自己声明一切**」（artifactType 开放、数据/预览/模式都在模块目录内）；
我们目前是「**壳知道每个模块、后端下发一切数据**」（中心 registry + 后端 artifact 驱动画布）。
前者加模块不改壳，后者加模块要动注册表；但后者的知识数据在后端，学生端无法离线自演示。
**最划算的融合**：保留后端数据，把「注册 + preview + 分发」三件事改成参考作品的自注册模式。
